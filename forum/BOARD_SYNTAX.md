# 棋盘语法 v1

正文、回复和正文编辑均支持同一种语法。直接输入，编辑器即时预览；发布和刷新后自动渲染。数据库保留原文，重新编辑时仍是原来的编码。

```text
[[board:4x4:fedcba9876543210]]
[[board:4x4:fedc/ba98/7654/3210|这里讨论下一步]]
[[board:2x4:1234/5678|小盘局面]]
```

## 格式

`[[board:变体:盘面编码|可选说明]]`

- 变体目前支持 `4x4`、`3x4`、`3x3`、`2x4`，表示行数 × 列数；`×` 也可代替 `x`。特殊赛事规则/障碍物盘面尚未纳入该语法，不能以尺寸推断其规则。
- 按从左到右、从上到下的顺序，每个字符表示一个格子。沿用 Play 练习模式的指数编码，兼容普通十六进制盘面，并扩展至 `k`。
- `0` 是空格，`1` 是 2，`2` 是 4，依此类推；`a` = 1024，`b` = 2048，`c` = 4096，`d` = 8192，`e` = 16384，`f` = 32768，`g` = 65536，`h` = 131072，`i` = 262144，`j` = 524288，`k` = 1048576。
- 大小写均可，可带 `0x` 前缀。连续短编码按 Play 的约定在左侧补 `0`；例如 `[[board:2x4:12]]` 仅在最后两个格子放 2 和 4。超过格数的编码会报错，绝不截断。
- 可选的 `/` 是行分隔符。使用分行形式时，必须明确写全每行的每个格子；`2x4` 对应 `1234/5678`。语法整体写在同一行。
- 第一处 `|` 后是说明，最多 500 个 UTF-16 码元（与网页输入限制一致）；不允许换行或 `]]`。说明按纯文本显示，不能嵌入 HTML 或嵌套棋盘。
- 正文可混排文字与多个棋盘，每篇正文最多转换 20 个语法棋盘。超出的保留原文；手绘的结构化棋盘继续沿用原有文档限制。

## 显示示例原文

用单个或多个反引号包裹语法，包括反引号围栏代码段，阅读器不转换里面的内容。当前正文尚不是完整 Markdown 阅读器，反引号本身也作为原文显示。未闭合的反引号会令之后的内容保持原文。

另一种方式是在开头加反斜杠：`\[[board:4x4:1]]`。显示时去掉这个转义反斜杠，保留语法文本。

输入不完整、变体未知、编码非法或行数不匹配时，编辑预览提示原因，发布后保留原文，不猜测盘面、不阻止其作为普通文本发布。

## 用户操作

- 正文下的「用语法插入棋盘」提供速查与「插入棋盘示例」，在当前光标位置插入。
- 棋盘下的「复制棋盘语法」产生连续、完整、规范化编码，可用于新帖或回复；「查看语法」支持手动复制。
- 已有手绘棋盘也可复制成同一种语法。说明含换行或结束符 `]]` 时，暂不提供可能丢失信息的转换。
- 编码棋盘标记为「编码局面 · 非正式成绩」。语法仅描述静态盘面，不证明对局真实性、不执行游戏动作，也不请求远程资源。

## 开发约定与验证

实现位于 `frontend/src/boardSyntax.js`。`Document.vue` 在阅读时派生棋盘块，源 `paragraph.text` 不被替换；草稿、发布、修订和搜索继续使用 PostgreSQL 中的原文，无需迁移数据库。未来服务端生成分享图或邮件时应复用此语法规范及测试样例，不能另行猜测编码方向。修改旧语法语义必须考虑历史帖子，扩展规则应用显式的新标记。

`npm test` 包含 19 项解析测试，直接与主站 `frontend/src/human/practice.js` 的编码/解码结果比较，并覆盖行方向、高位数、大小写、短码、转义、错误输入、混排和跨段落数量限制。PostgreSQL 集成测试另行验证发布、检索、编辑和回复的源文本不丢失。浏览器验证了插入、即时预览、错误提示、发布、刷新、编辑保留源码、回复和手机布局。
