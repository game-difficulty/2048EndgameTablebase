# 赛事房间阶段视图与转场说明（选手站／直播站新版）

更新于 2026-09-29。文件名沿用首次审阅日期。本版以当前本地代码为准，同时审阅**参赛选手的独立比赛站**与**从直播大厅进入的观众视图**；“设计目标”和“当前实现”在下文分别表述，未完成的观众功能不能视为已经上线。

文中图片均由本地前端加载模拟服务器快照生成。比赛站为 1440 × 900 视窗；直播站为 1600 × 1000 网页，其中内容舞台仍使用固定比例。姓名、项目组合、比分和棋盘均为示例。截图展示阶段稳定态，**不证明真实多人同步、连续转场或线上部署**；直播模拟页外壳中的聊天取数提示与真实比赛无关。19 张选手阶段图和 10 张直播图保存在同级的 `competition_stage_images_20260929_v2/`，旧版图片保留不覆盖。

## 1. 结论与流程边界

选手站的主线、身份权限和赛中双棋盘已经基本按设计工作：队长独占 BP／布阵／结果确认；队员可看本队已提交阵容；当局出战者只能操作本方棋盘，但所有参赛选手都能实时看对手棋盘。密封候选和对方秘密布阵在服务端投影阶段裁剪，不能靠前端遮盖保密。

直播站的公开 BP、秘密信息边界和双棋盘可用；**抽签结果、开局就绪、局间结果和最终结算的观众表达尚不完整**。比赛站最近新增的“当前玩法规则”页底说明目前也未进入直播内容。直播大厅是观众入口；候场和双队长准备期间尚无直播房间，进入 `DRAW` 后直播才开放。

| 顺序 | 服务端状态 | 选手站主窗口 | 直播观众当前窗口 | 正常推进条件 |
| --- | --- | --- | --- | --- |
| 01 | `SEATING` | 六席落座 | 不开放直播 | 六席满员 |
| 02 | `READY_CHECK` | 双队长准备 | 不开放直播 | 两队队长均准备 |
| 03 | `DRAW` | 先手抽签揭晓 | BP 容器，缺先手揭示 | 揭晓期结束 |
| 04–05 | `FIRST_PICK_BAN`／`SECOND_PICK_BAN` | 队长依次选 A/B、BAN M/N | 公开项目池与已锁定项 | 分别提交或各自 60 秒超时 |
| 06 | `BLIND_PICK` | 双方秘密选 C 候选 | 仅显示密封状态 | 分别提交或各自超时 |
| 07 | `C_DRAW` | 公布候选并抽定 C | 公布候选与 A/B/C | 揭晓期结束 |
| 08 | `LINEUP` | 双队长秘密布阵 | 只见提交状态 | 双队提交或各自 180 秒超时 |
| 09／12／15 | `GAME_*_READY` | 本局开局检查 | 仍复用密封布阵卡 | 双方出战者和队长就绪后自动开局 |
| 10／13／16 | `GAME_*_PLAYING` | 双棋盘、队员侧翼、本人操作 | 双公开棋盘 | 双方完成或包干时间裁决 |
| 11／14／17 | `GAME_*_RESULT` | 本局成绩与队长确认 | 仍复用双棋盘 | 双队长确认后自动推进 |

常规主线**不要求裁判启动项目**。A 局由双方出战者和队长全部就绪触发自动开局，双方 60 分钟包干时钟此时首次从 `stopped` 变为 `running`；B/C 局仅恢复剩余时间。裁判介入属于暂停、改判、强制推进等异常路径。

## 2. 共用信息与转场规则

选手站赛前沿用房间标题、黄左白右布局和阶段条；从 `GAME_*_READY` 起改为顶部单条赛事 HUD。系列局分分别写在黄方和白方区域，不挤在中央项目图旁；中间是放大的项目图标、名称和 A/B/C 进度。两侧包干时间始终在各自阵营；`PLAYING` 时两块棋盘上方分别显示本侧成绩、项目计时及步数。双棋盘下方的小字提供当前玩法规则，主要供旁观者理解。桌面端优先保留棋盘尺寸，窄屏时两棋盘上下排列。

计时必须分清两层：顶部为各队跨三局继承的**包干时钟**；棋盘附近为双方各自的**项目时钟**，竞速类正计时，固定时长项目倒计时。某侧完成或暂停后，只冻结应被冻结的时钟。盲选、布阵有双方独立截止时间：选手只看本队剩余与对方提交状态；直播现阶段显示的是阶段剩余时间，不应解读为两队共用一只倒计时。

当前选手站仅在同一房间收到**相邻状态**的新服务器快照时播放阶段动效。普通页面以约 220–280ms 的淡入／轻移切换；抽签、项目锁定、C 揭晓、开局、赛果和全场结算使用各自短提示。刷新、重连或跳过多个状态时直接显示最新权威状态，不补播旧动画；减少动态效果设置下退化为短暂状态变化。以下截图是稳定态，不是动效录像。直播站尚没有与选手站等价的整套阶段转场，不能把选手端动效描述套用到观众端。

## 3. 逐阶段：画面、权限与切换

### 01 · 落座 `SEATING`

![选手落座](competition_stage_images_20260929_v2/01-seating.png)

选手看到黄／白各三席，1 号为队长席。空位可选，已落座显示头像、昵称和本人标识；最后一席被服务器接受后，人数变为 6/6 并切到准备。观众尚无直播入口。席位更新为轻位移／淡入，不弹阻断窗口。

### 02 · 双队长准备 `READY_CHECK`

![双队长准备](competition_stage_images_20260929_v2/02-ready-check.png)

六席固定，只有两队队长可操作本队准备；普通队员只读。第二位队长准备被服务端接受后进入 `DRAW`，无需主办方或裁判放行。观众仍无直播入口。按钮的提交态不能伪装成已获服务器确认。

### 03 · 先手抽签 `DRAW`

![选手抽签](competition_stage_images_20260929_v2/03-draw.png)

![观众抽签当前画面](competition_stage_images_20260929_v2/live-draw.png)

选手中央看到服务端已确定的先手方、队长和抽签承诺；实时相邻切换时黄／白徽记短暂交替，约 900ms 后停在权威结果。直播从此阶段出现在大厅，但当前直播组件只显示“抽签”和项目池，**没有消费公开投影中的 `first_side` 来指明谁先手**。这是观众端待补，而非抽签未完成。揭晓期结束进入先手选禁。

### 04 · 先手选 A、BAN M `FIRST_PICK_BAN`

![选手先手 BP](competition_stage_images_20260929_v2/04-first-pick-ban.png)

![观众先手 BP](competition_stage_images_20260929_v2/live-first-pick-ban.png)

先手队长在项目池中暂选不同的 PICK 与 BAN，再提交锁定；本队其他人及对方只能看公开信息，不见未提交暂选。观众可见先手行动方、倒计时、项目池与已公开槽位。提交或超时后服务器公布 A/M，选手端图标飞入槽位并标出“队长锁定／超时自动”，随即进入后手的独立 60 秒回合。

### 05 · 后手选 B、BAN N `SECOND_PICK_BAN`

![选手后手 BP](competition_stage_images_20260929_v2/05-second-pick-ban.png)

![观众后手 BP](competition_stage_images_20260929_v2/live-second-pick-ban.png)

A/M 已公开并不可复选；后手队长选择 B/N。本阶段有独立的 60 秒截止时间，不继承先手剩余秒数。观众只见已锁定事实，不见后手本地暂选。服务器接受后以同类入槽／BAN 置灰效果切入双方盲选。

### 06 · 双方盲选 `BLIND_PICK`

![选手盲选](competition_stage_images_20260929_v2/06-blind-pick.png)

![观众盲选](competition_stage_images_20260929_v2/live-blind-pick.png)

两队队长各自秘密选 C 候选，独立倒计时和提交；队员默认只见提交状态，队长可核对本队已提交候选。观众只见黄／白“等待／已密封”，候选 X/Y 不提前出现。服务端公开投影确实在 C 揭晓前裁掉 `blind_choices`；这不是仅靠界面隐藏。双方结束后转入候选公开。

### 07 · 公布候选并抽定 C `C_DRAW`

![选手 C 揭晓](competition_stage_images_20260929_v2/07-c-draw.png)

![观众 C 揭晓当前画面](competition_stage_images_20260929_v2/live-c-draw.png)

选手页放大的三张项目图卡展示 A/B/C、规则短句、候选来源与两项 BAN。实时相邻切换时先显示候选，约 430ms 后显现候选内容、约 1050ms 后显现 C；最终项目只取服务器结果。观众页能显示两队候选与选定 C，但尚未实现等价的揭晓短动效。揭晓期结束进入秘密布阵。

### 08 · 双方秘密布阵 `LINEUP`

![选手布阵](competition_stage_images_20260929_v2/08-lineup.png)

![观众布阵](competition_stage_images_20260929_v2/live-lineup.png)

队长为 A/B/C 各派一人，且三名队员各出战一次。本队提交后全队可核对本队完整编排；对方和观众仅见“布阵中／已密封”，不见 A/B/C 对应队员。超时按 1/2/3 默认编排。服务器完成双队布阵后切到 A 开局检查；未来场次的出战者仍不公开。直播页目前显示密封状态及阶段计时，未展示队长的私有编辑过程。

### 09 · A 开局检查 `GAME_A_READY`

![选手 A 开局检查](competition_stage_images_20260929_v2/09-game-a-ready.png)

![观众 A 开局检查当前画面](competition_stage_images_20260929_v2/live-game-a-ready.png)

选手站顶部切换为单条赛事 HUD；两队包干时钟仍停在 60:00。主体突出放大的 A 项目图与规则说明，再列出当局双方就绪状态。本队选手可见本队出战安排，**对手身份要等项目实际开始才公开**。当双方出战者与队长均就绪，服务器自动创建会话、启动两队包干计时并进入双棋盘。当前没有独立的 3–2–1 页面。直播站仍复用三张“密封阵容”卡，既不显示实际就绪进度，也把原始状态名 `GAME A READY` 直接显示给观众；公开投影尚需补充不泄露出战安排的就绪字段。

### 10 · A 对局 `GAME_A_PLAYING`

![选手 A 对局](competition_stage_images_20260929_v2/10-game-a-playing.png)

![观众 A 对局](competition_stage_images_20260929_v2/live-game-a-playing.png)

选手站的两个棋盘等权并列，黄／白三名队员贴两侧排布，当前出战者头像以队色强调。出战者只能操作本侧，但能实时看对手；队长及候场队员也能看双方公开棋盘。两侧分别显示成绩、独立项目时钟和步数，底部有小字玩法规则。直播站有双公开棋盘、当前选手与项目进度，但**没有完整三人侧翼，也没有当前项目规则说明**。某侧先完成时只标记该侧完成并停本侧计时；另一侧继续，双方结束前不公布胜方。

### 11 · A 结果确认 `GAME_A_RESULT`

![选手 A 结果](competition_stage_images_20260929_v2/11-game-a-result.png)

![观众 A 结果当前画面](competition_stage_images_20260929_v2/live-game-a-result.png)

![选手 B 开局检查](competition_stage_images_20260929_v2/12-game-b-ready.png)

![选手 B 对局](competition_stage_images_20260929_v2/13-game-b-playing.png)

两侧队员和棋盘锚点保持不变，只更新项目、出战者、局分及独立计时。对抗出数的“AI 思考中”只在本选手盘附近出现，思考未出数时禁止继续输入；观众仍看双方权威棋盘。直播站继续使用双项目公开画面，但缺规则短句与三人侧翼。双方完成后公布 B 结果。

![选手 C 结果](competition_stage_images_20260929_v2/17-game-c-result.png)

### 18 · 全场结算 `FINISHED`

![选手全场结算](competition_stage_images_20260929_v2/18-finished.png)

### 异常分支 · 暂停

![选手 B 对局暂停](competition_stage_images_20260929_v2/19-suspended.png)

暂停叠加在当前 `GAME_*_PLAYING`，不是新的主线阶段。选手站保留双方棋盘，冻结操作与时钟，显示公开原因、发起者及恢复就绪状态；队长准备恢复，裁判负责真正恢复。直播站目前只有公开“比赛已暂停”提示，足以表达基本状态，但缺更细的公开原因与恢复进度。恢复后继续原会话，不新开棋盘或重置时钟。

## 4. 待补项与验收顺序

| 优先级 | 观众端待补 | 所需边界／验收点 |
| --- | --- | --- |
| 高 | 抽签明确显示先手方 | 使用已公开的 `public_draft.first_side`；刷新直接显示结果，不重抽 |
| 高 | `GAME_*_READY` 独立检查画面 | 公开投影增加双方就绪汇总，不能提前泄露本局／未来出战者 |
| 高 | `GAME_*_RESULT` 独立成绩与确认画面 | 使用权威 `games[].result` 与 `captain_confirmation_status`；清楚区分本局成绩与系列局分 |
| 高 | 直播赛中当前玩法规则短句 | 直接使用已公开的项目 `description`，不压缩双棋盘 |
| 中 | 直播结算补逐局分数、出战者、异常来源 | 使用公开结果与已开赛名单；无回放能力时明确写“暂无回放”，不要虚构入口 |
| 中 | 直播开局／结果阶段中文标签与转场 | 不直接显示 `GAME A READY` 等状态码；以服务器状态切换，刷新不补播 |
| 中 | 直播赛中三人状态侧翼 | 只展示公开席位和当局已揭示的出战者，不推断在线状态或未来安排 |

选手站仍需真实多人房间联调：独立项目倒计时、暂停／重连、单方先完成、项目限时结束、裁判改判后旧确认失效，以及匿名观众从直播大厅进入后的持续更新。当前本地后端公开投影与直播接入相关的 11 项测试通过，但模拟截图和单元测试都不能代替这些端到端验收。
