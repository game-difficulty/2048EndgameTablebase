# 人类玩家独立站：背景调查与总体设计 v0.2

> 2026-09-24 归档范围修订：自然死亡局无论分数都尝试上传；重开、放弃等非自然结束仅在得分严格超过对应变体高分阈值时上传，低分和等于阈值者只保留本地，不进入补传队列。高分非自然结束局失败静默处理，保留原有重开保护，死亡局失败仍提醒保存回放。以下早期“全部重开/放弃局云归档”的建议被本条替代。

日期：2026-09-23。状态：讨论稿，不代表已经实现或最终定案。

背景调查基于 `src - cloud` 当时的工作区（HEAD `57e1860`，含大量已有未提交修改）与 2048verse 的公开页面。本轮只调整本文档，不改业务代码、不部署。现有迁移文档部分停留在 7 月，因此实现现状以调查时的代码为主；没有核对远端生产部署版本、线上负载或真实存储规模。v0.2 按用户明确的浏览器隔离、高分门槛、单向存档及强制联网规则修订，替代 v0.1 中账号全局单局、云端恢复与全程周期上传等建议。

## 1. 产品目标与推荐取舍

建立一个以人类独立思考、成绩可复算、历史可复盘为中心的 2048 站点。首版理解为四种棋盘的单人冲分与异步排行榜，不包含实时 PvP、匹配、聊天或赛事直播。

建议采用独立子域名、独立前端入口、共享账号身份与基础组件、独立对局档案和人类排行榜。例如 `play.2048tables.online` 只是命名建议，尚未确定或配置。

最重要的四条设计原则：

1. **进行中对局仅以当前浏览器的本地存档续玩**，服务端保存上传证据并验证，绝不下发进度恢复或覆盖本地棋盘。已验证的历史档案是个人最佳、排行榜和个人统计的事实来源；离榜、刷新 PB 不得删除历史回放。
2. “规则复算通过”“满足排位规则”“经过人工复核”分别表达，不能合并成“已证明是人类”。
3. 本地持久化、高分联网校验、历史归档是三件事。高分断线锁住正式局，重入只检查本地是否延续服务器已留档前缀；本地落后判定回档/作弊，后台故障本身不判作弊，也不能触发云端恢复。
4. 规则、随机算法、记录协议、计时政策均需版本化，保证数月后仍能解释和重放一局。

建议首版默认：标准 90% 出 2 / 10% 出 4、两枚初始棋块、正式局禁止悔棋、AI 和查表；允许不提供答案的练习板，四种棋盘各自独立分数榜。达到 2048 或其他目标块后继续游戏，不强制结束。

**用户已明确的规则：始终允许练习，不需要标记，也不影响原局排位资格。**练习帮助玩家观察不同随机出数后自行思考，不提供 AI、查表、推荐走法或成功率。可以局中跳转、反复演练后回到原局继续；原局不记“使用过练习”标签，不分辅助榜。练习棋盘本身标明“练习”，仅用于避免误操作，不能成为对原局的降级或标记。后文均以此为前提。

**v0.2 已确定的运行约束：**

- 同账号同浏览器的四种变体可以各自保有一局；同变体只能有一个正式进行中对局，多标签页不能分叉。
- 不同设备或浏览器的进行中存档互不共享，不提供跨设备/浏览器续局；账号身份、已归档历史和排行榜仍可按权限查看。
- 只有得分 **严格超过**该变体阈值的局才进入高分监管，启用周期上传并要求持续联网；阈值以下仍本地记录完整回放，结束后一次性归档。
- 高分重入时，本地有效步数必须大于等于服务端已接收进度，而且对应前缀必须一致；本地落后按回档/作弊处理，绝不从服务器加载棋盘“修复”。
- 高分断网时显示弹窗并禁止正式局操作，恢复连接并校验通过后继续本地局；当前版本不做服务器端逐步出数。

### 当前机制的重要限制

- Gamer 验证器与移动规则写死 4×4，提交 final_board 也要求 16 格。
- Gamer 种子通过 `seed_hex` 下发浏览器，可确定性复算，但浏览器可以得知未来随机流。
- 当前主站可以记录 `used_ai`，排行面板也显示 AI；它不是独立的禁止 AI/查表的人类榜。
- 主站允许 10%～80% 出 4 概率，且存在难度变化/恶意出数分类。新站标准榜应固定规则，不能只换榜名。
- 当前回放放在 `gamer_high_scores` / `gamer_weekly_high_scores` 的 `record_blob TEXT`；PB 会替换，榜单会裁剪，非 PB 的上传内容被清除。默认每榜保留 100 条，可配置范围为 100～1000，旧周榜也有清理。
- 当前普通提交有日限额与优先候选策略；不能直接承接“每局都上传归档”。归档限流与高成本审核限流需要分开。
- Gamer 异常路径存在把一般验证异常记为 `validation_failed` 的行为；新站应借鉴小游戏的可重试故障处理，区分格式错误、规则不符与基础设施不可用。
- 现有共享 cookie 的存在不意味着新子域自动可用。还需核对认证主机白名单、同源 API 代理、写接口 Origin/CSRF 防护和 WebSocket Origin。

## 3. 参考站观察及采用边界

实际查看了 [2048verse 首页](https://2048verse.com/)、[3×4 游戏页](https://2048verse.com/3x4) 和 [规则页](https://2048verse.com/rules)。

- 首页提供 4×4、3×4、3×3、2×4；游戏页有当前分数、最高分、新游戏、练习、回放、统计和排行榜，榜单昵称可进入个人页。
- 3×4 实际显示为 **3 行 4 列**。现有 Verse 解码注释也说明其尺寸采用 rows × columns。建议新站对用户沿用行×列命名，内部显式使用 `rows/cols`，避免把 3×4 做成 4 行 3 列。
- 规则要求本人合法对局，禁止外部 AI/查表、过度喂招、回退作弊、绕过反作弊等。这是公开行为规范，不能据此推断其私有反作弊技术。
- 参考其紧凑布局、练习/回放路径和玩家入口，不复制其品牌、素材，也不照搬特定分数门槛或处罚方式。

## 4. 页面与对局体验

### 桌面布局

```text
站点导航 | 4×4 / 3×4 / 2×4 / 3×3 | 对局记录 | 玩家 | 账号
┌────────────────┬────────────────────────┬──────────────────┐
│ 本局用时       │ 当前分数 / 个人最佳     │ 当前变体排行榜   │
│ 节点累计时间   │ 模式、保存/排位状态     │ 总榜 / 周榜      │
│ 节点区间时间   │                        │ 前十 + 我的排名  │
│ 与个人 PB 对比 │         棋盘           │ 玩家页 / 回放    │
│                │                        │ 查看完整榜单     │
│                │ 重开 / 暂停 / 去练习   │                  │
└────────────────┴────────────────────────┴──────────────────┘
```

手机优先完整展示棋盘、分数和资格状态；节点、排行榜、历史放入折叠面板或底部页签，不能把三栏缩成三条窄栏。四种尺寸使用同一套输入、动画和无障碍组件，矩形棋盘保持正方形单格。

页头明确区分“人类排位”“非排位对局”“练习”“访客”；状态另外显示“本地已保存至第 N 步”“高分联网校验中”“服务端已留档至第 M 步”“需联网才能继续”。不能将本地保存显示成云保存。去练习后回来仍是同一个“人类排位”状态；高分局仍须满足联网与重入校验。

首个有效移动开始计时。按住方向键、触屏连续滑动、动画未结束输入等行为必须有统一队列规则；首版不开放宏和自动连步功能。无效移动不出数、不增步数，其耗时计入到下一有效动作前的间隔。

### 重开保护

- 所有真正重开入口（按钮、R、明确清空该局的操作）进入同一处理逻辑。**切换变体只是切换独立存档槽，不重开、不清空、不结束原变体的局**；返回时从该浏览器本地继续，高分局先做重入检查。
- 重开保护阈值按变体配置，可综合已达目标块、超过一定分数、长时对局、接近或超过个人 PB；不要用一套 4×4 高分阈值覆盖四个变体。它与联网监管的 `monitor_score_threshold` 是两个独立设置，不能互相替代。数值在试运行后确定。
- 高价值对局弹窗展示分数、最大块、用时、存档状态；默认焦点是“继续本局”，Esc 取消。
- 已确认重开后将旧局本地封存为 `restarted` 并排队上传，再在同一变体槽创建新 run。服务端槽位替换需原子、幂等，旧局待上传历史与新局进行中状态分别保存；新局创建失败不得抹去旧局或重复创建。
- 弹窗期间清空待执行移动，阻止按键穿透；忽略重复 keydown、输入框内的 R、输入法组合输入。
- 正在上传时不把“重开”变成无法退出的死锁。可先保留本地待上传队列，但必须显示未完成云归档。断网时可明确放弃并保留旧局记录；创建新的服务器绑定排位局仍需联网，不能借重开让旧高分局离线续玩。
- 刷新仅从本地恢复候选状态，不默认重开；高分候选在校验通过前不可操作。本地丢失时不提供云端恢复按钮。浏览器关闭提示只是补充，不能当作存档保证。

## 5. 对局分类与排行榜规则

| 类别 | 允许能力 | 是否进入人类榜 | 历史记录 |
|---|---|---|---|
| 人类排位 | 标准规则、人类操作、正式局无悔棋/AI/查表；始终允许独立练习 | 满足资格且验证通过后；练习不影响资格 | 全量 |
| 非排位对局 | 导入、非标准规则或证据不完整的继续对局 | 否；使用练习不是转入此类的理由 | 全量，保留原局身份 |
| 练习 | 任意摆盘、手动出数、撤销重做、随机演练 | 否 | 登录用户的练习局也应纳入存档设计，默认不公开 |
| 访客或离线未绑定局 | 可自由游玩 | 否，不事后追认为排位 | 本地保存与导出；登录后可导入为个人非排位档案 |

首版“全部历史”建议明确覆盖登录用户的所有新站正式对局，包括失败、重开、放弃和非排位局；练习会话是否同样全量云存档可以另行决定，不影响正式局的留存。零有效移动的建局保留小型元数据即可，初始棋盘足以重建。纯编辑中间态可作为同一练习会话的编辑事件，不必每次摆块创建一局。对于从未到达服务器且本地也丢失的动作，任何网站都不能承诺完整云回放，界面应如实展示已归档前缀。

“全历史归档”不等于“所有局周期上传”：未超过阈值的局全程在本地记录，结束/明确重开/放弃时一次上传；当时离线则放入本浏览器的归档队列，下次联网补传，可批量处理短局。仅离开页面但没有结束的低分局只本地保存，不额外启动周期上传。高分局另有周期证据。历史回放可跨设备只读查看或开练习，不能载入为正式进行中存档。低分局若在终局上传前连本地数据也丢失，只能承认档案缺失，不能凭空补齐。

### 排序与统计口径

- 四变体分榜，榜键包含棋盘、规则版本、计时政策/核验等级（如果参与比较）；不按是否使用练习分榜。
- 自然结束且完整复算通过的局自动上榜。非自然结束的局（如本地丢档、服务器仅剩未死亡局面的临时留档）默认不上榜，但站长可审核后手动准入；成绩只能取服务器已保存且全量复算通过的最后一步。保留真实结束原因，封存后不能续玩，不恢复或覆盖玩家本地进度。手动准入和撤销均记录操作者、理由、时间及证据哈希，并同步影响榜单、分数 PB 和公开回放权限。
- 同分建议共享名次，显示顺序再按服务端达成时间、run_id 稳定排序；不要暗中用不可靠的客户端时间作同分胜负。
- 每用户每榜默认只显示最好一局；另设“全部高分对局”视图，避免少数用户刷满主榜。
- 周榜采用 UTC+8 周一 00:00 边界，与现有站点一致。分数榜按服务端接收终局的时间归周；手动封存临时留档使用最后一批有效动作的接收时间，已有归档保留原结束时间，审核延迟不能改变归属。跨周、延迟补传的规则提前公示。
- 首版不做四变体综合 Elo：单人随机局缺乏直接对手与统一难度尺度。
- 成绩卡显示验证状态、规则版本、结束原因、回放完整性。异常提交先待复核，不在公开页面直接标“作弊”。
- 老主站成绩和外部导入回放可作为“导入/历史记录”，不能凭合法回放直接变成人类排位成绩。

## 6. 节点计时：先定义时间，再画侧栏

节点事件由验证器在首次合并得到目标块时计算，记录 `tile, move_seq, score, elapsed_ms`。初始摆盘自带的目标块不算新达成。后续同样大小的第二枚棋块不覆盖第一次。

建议配置（初始建议，不是与参考站完全一致的规则）：

| 棋盘 | 默认显示节点 |
|---|---|
| 4×4 | 512、1024、2048、4096、8192、16384、32768、65536，继续动态扩展 |
| 3×4 | 128、256、512、1024、2048、4096、8192 |
| 2×4 | 32、64、128、256、512、1024 |
| 3×3 | 64、128、256、512、1024、2048 |

同时保留三种时间，不混用：

1. **连续经过时间**：从首个有效移动到指定步，包含思考、练习、切后台、暂停和断线。建议作为默认节点展示口径，去练习不会停掉原局计时；这是统一耗时定义，不是对练习的惩罚或标记。
2. **活动会话时间**：显式暂停之外的游戏会话耗时，只用于个人分析；前台停留时间不能等同于实际思考时间。
3. **服务端观测时间**：建局、动作/批次接收、断线和封局时间，是审核证据；批量上传只能提供时间区间，不能证明每一步的准确耗时。

浏览器会话内使用单调时钟记录差值；刷新、设备休眠、系统时间修改后需利用服务端锚点恢复，并标记时间可信度。时钟异常不影响合法动作的历史留存，但可能失去计时榜资格。

首版节点时间用于复盘和自我比较，不立即推出严格速通榜。跨设备/浏览器续局不支持。未来速通需另定暂停、联网锁定耗时、服务器计时及网络延迟政策；服务器收包计时也不是精确的人类按键计时。当前连续经过时间建议包含联网锁定期间，不把网络恢复自动变成减时功能。

点击节点可跳至回放相应步。与个人 PB 的差值必须基于同一变体、同一时间口径；首版比较个人最佳整局的对应节点，可后续增加“各节点独立 PB”。

## 7. 反作弊方案与真实能力边界

### 威胁与应对

| 风险 | 可实施措施 | 仍然存在的边界 |
|---|---|---|
| 伪造分数、棋盘、出数 | 服务端从初始状态逐步复算，不相信客户端声明 | 合法动作可能来自 AI |
| 重写已经提交的过去 | 服务端只追加日志、连续序号、前缀摘要、不可覆写 ACK | 尚未提交区间仍可被搜索和重写 |
| 多标签页回退/分支择优 | 按账号＋浏览器实例＋变体唯一活跃槽，槽内写入锁/epoch，旧写入者拒收；高分重入检查前缀 | 不做账号全局单局限制；客户端浏览器标识不是不可伪造的设备证明 |
| 同一包重复提交 | run_id + seq 范围 + 摘要幂等；冲突包明确拒绝 | 单纯客户端自带哈希不具备身份真实性 |
| 预知随机流 | 当前仍使用预发种子，规则禁止预知利用，保留高分证据并审核 | 本版不做服务端出数，不能消除预知风险 |
| 大量重开挑种子 | 开局限速、尝试元数据、同浏览器同变体单活跃局、异常速率审核 | 正常玩家也会重开，不应仅凭次数定罪 |
| 外部 AI/查表/喂招 | 行为规范、站内辅助隔离、异常模式审核、顶尖成绩复核 | 网页无法可靠证明玩家没有使用第二设备 |
| 修改计时 | 双时钟证据、上传窗口、异常标记、独立计时资格 | 批量本地时间不是可信速通证明 |
| 恶意上传和资源消耗 | 压缩前后大小上限、步数上限、解码预算、队列公平调度 | 必须避免把正常高分长局当超额垃圾丢弃 |

焦点变化、设备/IP 变化、很快或很慢的操作都只能作为信号。不能凭 DevTools、切屏、共享 IP、VPN、AI 一致率单项自动封禁。允许的练习不是可疑行为，也不构成审核触发条件。站内 AI 接口不能把隐藏按钮当安全边界：可记录同账号活跃排位期间的 AI/查表调用作为复核线索，但不能证明被查询的局面就是该排位局。练习板不调用这类服务。

### 当前确定的随机协议

采用 **预发种子＋客户端出数＋超过阈值后联网监管**。服务器提前生成并绑定种子、run_id、账号、浏览器实例和变体；正式局创建需要联网。已绑定局未超过阈值时可本地离线继续，严格超过阈值后必须联网，不等到下一次周期上传才启用限制。

客户端始终计算移动和出数，服务端负责留档、连续性检查及规则复算。**当前版本不实现服务器逐步出数，也不再将其列为首版待选路线。**高分联网不意味着每步请求服务器出数。

已确认前缀不可改变，但预发种子仍有预知与客户端模拟风险，周期上传之间也存在未确认窗口。前端联网锁不能阻止被修改的客户端假报在线，服务端还需检查上传时序、连接许可和连续性。这些措施降低部分作弊空间，不能证明每一步都由人类完成。

## 8. 浏览器隔离、高分周期上传与重入校验

### 8.1 进行中存档的隔离与唯一性

正式进行中槽键固定为 `user_id + browser_instance_id + variant_id`，不将规则版本加进槽键来规避同变体单局约束。每个槽最多一局；同账号同浏览器的 4×4、3×4、2×4、3×3 可以并存，并且允许不同标签页操作不同变体。

`browser_instance_id` 是当前设备、浏览器配置文件及站点存储实例的持久随机标识，不用 IP、User-Agent 或侵入式指纹代替。同设备不同浏览器/配置文件和不同设备是独立实例；同一实例的多个标签页共享该标识、IndexedDB 和同变体写入锁。标识只用于存档归属，不宣称为不可伪造的设备身份。

- 同槽多标签页共用同一局，只有一个写入者；其他标签页提示前往原标签页或在安全释放后切换写入者，不能自动生成另一局。切换写入者也只读取共享本地存档。
- 本地事务/浏览器锁负责全部分数阶段的单写入；服务端建局唯一约束与写入 epoch 防止冲突建局和旧标签页提交，不因此给低分局增加周期心跳。
- 服务端唯一约束作用于上述槽键，不是 user_id；同账号其他变体、其他浏览器开局不抢占现有槽。允许槽内重开替换，不允许跨实例接管。
- 本地状态也按账号分区；退出登录/换账号不能把前一账号局绑定给后一账号。回到原账号仍只使用本实例原本地局。
- 不同步进行中棋盘、动作尾部、RNG 或续局密钥到其他实例；不要使用浏览器同步存储功能搬运这些数据。复制导入的回放只能查看/练习，不能跨实例续排位。
- 清空站点存储、无痕会话结束或本地损坏不触发云恢复。旧局在原槽保留证据，丢失的本地局不能续玩；新实例只可明确新开局。浏览器标识本身不能可靠识别恶意克隆或清空，结合建局/重开限流与审核处理，不能承诺硬件级防护。

### 8.2 高分阈值与首次上传

每个变体独立配置 `monitor_score_threshold`；当前分别为 4×4 800000、3×4 70000、3×3 10000、2×4 5000，不以 4×4 的同一分数覆盖所有变体。建局时绑定阈值与政策版本，运行中配置更新不改变这局已承诺的规则。**score > threshold 才进入监管，score == threshold 仍属低分阶段。**一旦进入就不可撤销；恢复旧低分快照或修改前端标记不能回到低分模式。

| 阶段 | 本地记录 | 服务端动作 | 是否允许离线正式操作 |
|---|---|---|---|
| 未超过阈值 | 完整动作日志与当前状态 | 建局；无周期上传/监管心跳；终局时一次归档 | 已绑定局允许 |
| 首次超过阈值 | 先原子保存刚完成的移动及出数 | 上传从开局到越线步的完整前缀，校验并登记高分状态 | 不允许离线；联网时后台验证，确认窗口内不中断走棋 |
| 高分阶段 | 继续完整保存 | 周期增量上传、连接检查、重入校验 | 不允许，失联锁住 |
| 已结束/重开/放弃 | 不可变本地终局与待上传队列 | 上传尚缺尾部并封局，低分亦归档 | 不再续玩；归档可在下次联网补传 |

越线发生在一次完整有效移动之后：原子保存该步结果并固定越线序号，立即后台校验；联网确认窗口内可继续走棋，新增尾部与首次前缀分开发送。网络不可达或验证失败才阻断正式操作。首次上传携带完整历史，服务端从种子复算越线分数与序号，不能只相信客户端自报分数。该步恰好 game over 时直接按终局处理，无须解锁棋盘，但上榜仍需完成归档验证。

首次上传太大时允许分块/流式接收，前缀完整且首次验证完成后发放常规在线许可；等待期间不持有棋盘输入锁。服务端已登记高分的局以该状态为准，即便重入客户端自报低分，也必须走高分检查。建局槽位映射和重入请求不能仅依赖客户端的 `monitoring=true` 字段。

### 8.3 仅高分局启用周期增量上传

当前高分阶段采用 **有新增动作时每 20 秒或累计 32 个未上传的有效移动**上传一次新增动作（先到为准）；高分节点、显式暂停、切换离开当前变体、退出页面时有新增尾部则尽力 flush。这是可调参数，不对低分局启用。没有新增动作不重复上传整局；需要续期时只传轻量连接信息。

同浏览器多变体并存时，可合并连接检查和网络调度，但各 run 的进度、回执、在线许可独立。停放在其他变体的高分局不需要不断重复写档；回到它时固定重入前的本地进度并后台检查，不能让检查期间新增移动掩盖回档。

每步将事件、棋盘/分数、RNG 状态和序号原子写入 IndexedDB，持久化完成才把该步作为可上传记录。**服务器 ACK 后仍保留本地完整进行中存档**，不能只剩待发送尾部，否则无法独立续局与重入比对。持久化失败时暂停正式输入并提示；服务器不负责补回本地数据。

周期分段的生命周期与对局状态绑定。对局成功封存后，服务端先用全部已收分段和终局尾部生成并验证最终压缩回放，再在同一写事务中将对局标记为 `sealed` 并删除该局的 `human_chunks`；封存局拒绝后续 `monitor`／`append`，客户端检测到结束原因后也停止周期触发。反过来，只要对局仍是 `active`，已收分段不设置按时间过期策略：联网许可过期、玩家长期离线、服务重启或数据库初始化均不得清除它们。它们只会在该局最终封存（含站长基于现存证据封存）后被最终回放替代。

协议示意：

```text
上传：run_id, browser_instance_id, writer_epoch, first_seq, last_seq,
      previous_receipt, events_binary, payload_hash, request_id
回执：durable_seq, validated_seq, prefix_hash, receipt,
      monitored, server_received_at, online_permit_expiry, retry_after
```

- `durable_seq` 是耐久保存且结构连续的前缀，`validated_seq` 是完成规则复算的前缀。结构错误的包不推进进度，规则复算失败使该局进入无效流程；验证队列暂时落后不能允许覆盖已接收前缀。
- 收包鉴权并检查归属、epoch、大小、序号与前驱；耐久追加之后才 ACK。周期复算只处理新增部分，终局/关键成绩再完整验证，避免累计 O(N²) 成本。
- 单槽串行发送，定时器/节点/退出触发合并；网络重试使用原 bytes、原幂等键。重复相同包返回原结果，相同序号不同内容明确拒绝，不能后写覆盖。
- 回执只含验证元数据，不返回可载入的棋盘、动作流或 RNG。进行中存档没有云端 load/restore 接口。

### 8.4 高分重入：只验证本地，不下载恢复

刷新、重新打开页面、从后台/其他变体返回、联网恢复，以及同浏览器写入者切换后，高分局都要发起校验。前端读取本地日志并冻结本次请求的序号和前缀快照，再请求该账号、浏览器实例、变体和 run 的服务端校验基准；服务端原子检查当前槽位与写入 epoch，避免检查后又被旧标签页更新。

“进度”以**有效移动序号及其对应动作前缀**定义，不只比较分数，也不拿不同局或不同浏览器的序号相比较。客户端提交本地序号和服务端指定位置的前缀摘要；服务端需要的新增尾部由本地上传，仍然是单向传输。

| 本地 L 与服务端已留档 S | 处理 |
|---|---|
| L < S | 判定该局回档/作弊，拒绝排位续玩/提交，保留本地和服务端证据；不把 S 的棋盘覆盖回来 |
| L == S 且前缀一致 | 后台检查连通性与写入资格，继续原本地棋盘 |
| L > S 且本地在 S 的前缀一致 | 正常本地领先；后台上传并检查 S 之后的尾部，绝不回退本地 |
| L >= S 但前缀不一致 | 分支/篡改冲突，按回档/作弊拒绝该局，不能因步数更大就放行 |
| 本地缺失/损坏，无法证明连续性 | 不允许该局续排位，记录具体缺失原因；不从服务器补棋盘，也不自动把基础设施问题判成账号作弊 |
| 服务端不可达、查询失败或确认窗口超时 | 锁住正式操作并稍后重试；不判回档，不下发进度替换本地 |

联网时等待校验本身不阻断输入，首次/重入采用单请求最多 8 秒的确认窗口；成功响应可推进下一验证阶段。L 固定为检查开始前的序号，新移动不更改这一回档判断基准。回执只更新确认元数据，不将发送时的旧棋盘覆盖当前进度。

其中 S 取当前已耐久接收的连续前缀，不是过期缓存或仅较小的 `validated_seq`。ACK 丢失时服务器可领先于客户端“已确认序号”，但只要本地完整日志 L 不落后就正常重试，不能误判作弊。本地内存棋盘与其完整日志不一致时只能从**同浏览器本地日志**重建显示后再验；日志本身落后/冲突不能用服务器修复。

回档判定首先作用于这局的资格和证据记录，是否进一步处罚账号由明确的审核政策决定，不自动扩大为全账号封禁。服务器重启、验证任务重试只恢复服务器自己的审核状态，不恢复玩家棋盘。

### 8.5 高分强制联网与锁定体验

- 超过阈值后必须维持与本站后端的有效连接确认，不能只相信 `navigator.onLine`。上传成功可以续期，空闲时按需轻量探测；连接许可绑定 run、写入 epoch 和已接收进度，不能用另一变体在线代替本局校验。
- 收到离线事件、连接关闭、实际请求失败或许可超时后，显示“高分对局需要联网，连接恢复后可继续”弹窗并禁止该正式局操作；清空按键/触摸队列，阻止自动重复、动画回调或快捷键绕过。可重试、退出或明确放弃，不能关闭弹窗后继续原局。
- 后台网络断开无法总在物理断开的同一瞬间被发现；心跳/许可超时规定的是技术检测上界，不是允许离线继续的产品宽限。具体探测周期和超时上限待负载测试确定；不得另设高分离线游玩模式。后台冻结期间没有动作，回前台固定本地进度并后台验证。
- 恢复连接后后台依次检查身份/本实例槽位、本地前缀并补传已有尾部，确认窗口内恢复操作，失败则锁定；不自动回放缓存方向，不调用云端恢复。网络或服务端故障只造成锁定，不自动判作弊或把原局降级后让其继续离线玩。
- 练习仍始终允许且不标记；联网弹窗锁住的是正式局，不应封死练习入口或其他未过阈值变体。独立练习不能修改或推进被锁的正式局；返回正式局仍需满足上述条件。

高分离开页面时使用 `visibilitychange` 尽力上传未确认尾部，`pagehide` 作补充；Beacon/keepalive 不传整局，入队成功也不等于服务端确认。低分离开只做本地持久化，已终局的历史另走一次性归档队列。退出事件不保证触发，尤其移动端，因此不存在“退出失败就从云恢复”的兜底。浏览器行为参考 [MDN sendBeacon 文档](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/sendBeacon)。

## 9. 全量回放、二进制压缩与可跳转

### 数据表示

优先复用并扩展现有 RPL1 语义，不急于再创造一个难以兼容的游戏格式；先验证四种尺寸、扩展字段和练习编辑事件能否无歧义表示。需要不兼容变化时使用新协议版本，不偷偷改变 v1 的含义。

归档外层保存：magic、format_version、rules_version、RNG/计时版本、rows/cols、run_id、初始棋盘/分数、结束原因、数据长度、压缩算法；不额外保存归档 SHA-256。身份私密信息、IP、认证令牌和审核明细不放入公开下载的回放。

正式局每步最小动作记录可沿用 1 字节（2 位方向 + 4 位出数格 + 1 位 2/4）与 ULEB128 毫秒差；四种棋盘最多 16 格，够用。正式局还需记录暂停、恢复、结束等事件；练习回放另支持摆盘、撤销等编辑事件。正式局不必记录练习使用标志。已记录出数有利于独立播放，种子与规则用于独立核验，二者不能相互替代。

棋块内部建议保存整数指数，分数用足够宽的整数；不要把“棋盘不超过 16 格”误解为“每格 4 bit 指数永远够用”。现有部分 hex/原生位板对大块有约束，必须测试 65536 及以上。协议上限、计分溢出、超长时间差需显式定义。

归档复用 gzip 自带 CRC32/长度检测意外损坏，不额外保存文件 SHA-256。完整规则复算与最终状态比对仍保留；防回档的动作前缀链和临时分段摘要不随归档摘要移除。CRC 不等于反作弊签名。服务端回执与已保存前缀才提供接收顺序证据。审核事件日志应与公开棋谱分离。

### 压缩与存储

- 数据库保存元数据和索引；原始棋谱用二进制对象保存，不继续 Base64 TEXT 长期归档。Base64 仅留作兼容导入导出。
- 低分活跃局的完整日志仅存当前浏览器，服务器只有建局元数据；高分活跃局服务端才保留追加日志和少量验证快照。封局收到完整回放后生成不可变压缩对象，原子写入索引。对象已落盘但数据库提交失败等窗口要有重试与孤儿对象回收。
- 初选 Zstandard 低/中等级，针对真实样本与 gzip 比较体积、CPU 和冷读取；不在设计阶段承诺压缩倍率。Zstd 是候选而非当前依赖已经可用的结论，参考 [Zstandard 官方说明](https://facebook.github.io/zstd/)。
- 首期可通过统一对象存储接口落本地文件 + 独立备份；规模增长后迁移兼容对象存储。需实际测量容量和写入量，不能因“全历史”三个字立即引入复杂集群。
- 上传接收不逐小包高等级压缩；可先耐久追加，封局合并压缩。验证只处理增量，封局再做一次独立完整检查用于关键成绩。
- 短局可能压缩收益很小，允许保存 raw 并记录 codec。大量极短局的文件/对象操作开销可能高于棋谱本身，可后期打包冷数据，但需保留每局偏移、校验和权限边界。
- 排名裁剪绝不触发归档删除。备份、迁移、完整性巡检、服务器档案灾备恢复演练和对象丢失告警属于首版全量存档的交付范围；这里的灾备恢复不是玩家云端续局。低分本地尚未上传的历史不在服务器备份中。

容量仅作预算示例：若平均 20,000 步、每步 3 字节（1 字节动作 + 约 2 字节时间），单局动作约 60 KB；100 万局约 60 GB，尚未压缩，未含快照、审核证据、索引和备份。实际需采样长局/短局、不同节奏后重新估算；不能把该数当作压缩后报价。

### 可跳转能力

- 永久链接形如 `/replays/{id}?step=12345`，节点链接也是步号锚点；失去榜单名次后链接仍有效。
- 在已归档回放中，每 256 或 512 步建立服务端验证的可重建快照与块索引；快照保存棋盘、分数、累计时间、事件偏移。高分局服务端内部继续验证时另保存 RNG 状态/计数器；不将这些快照或状态提供给进行中棋盘恢复。
- 短回放可以整局下载并建立内存索引；长回放按独立压缩块读取，不能对单个整局压缩流任意按未压缩偏移 seek。
- 审核与验算以动作日志为准，快照只是缓存，可以重建。跳到第 N 步后最多重放一个快照间隔。
- 播放器支持单步、进度条、倍速、节点列表、暂停间隔折叠及从当前步开练习；折叠等待只影响播放，不改原始计时。
- 回放读取接口与正式局运行时分离，只允许查看、导出或开启练习；没有“载入正式局继续”的入口/API。服务端进行中证据只返回校验元数据，不通过回放接口变相下发。

## 10. 练习板的独立性

从对局或回放第 N 步进入练习，默认复制那个时点的棋盘、棋盘尺寸、规则、来源链接；原局分数可以显示为“起始分数”，练习新增分数另列。不要使用移动后尚未出数的中间态作为默认跳转点。

每次练习使用独立随机源，默认 90%/10% 随机出数，不携带、不继续原局 seed/RNG 状态；“重新演练同一局面”默认重新随机。即使练习结果偶然与原局相同，也不能判断为复用种子。

提供两种互不混淆的编辑能力：

1. **手动出数**：完成合法滑动后，在空格放置 2 或 4；出数完成前不可执行下一步滑动。
2. **摆盘**：选择棋块值、点击/拖放任意格，可清空、撤销重做、重置来源局面、复制/粘贴标准局面串。退出编辑后开始新的练习分支。

练习明确标识，永远不能一键把练习板覆盖回原排位状态。练习失败或摆盘非法不影响原对局文件。需要记录编辑、撤销和分支才能保存完整练习回放，不能用正式局“只有方向与出数”的验证器强行验练习局。

未结束排位可直接进入练习，不弹资格警告、不请求降级、不写辅助标记。练习期间冻结原局棋盘与输入队列，保留本地原局与计时；低分局不增加网络任务，高分局按监管策略上传既有尾部，空闲时不重复写档。返回时继续原本地状态；高分局须先完成联网和重入检查。练习棋盘不能触发正式局的动作提交、消耗正式局 RNG 或改变正式局分数、节点。因后台节流导致许可到期时锁定并重新校验，不能因合法练习判作弊，也不能用云端棋盘代替本地。

已完成对局自由练习；纯手动摆盘可从练习入口直接进入。练习只提供规则模拟器，不显示推荐方向、成功率、期望分、局面评价或批量求解结果。继承主站的是摆盘和手动出数交互，不是主站的求解能力。原局与练习建议在同站双面板或独立页面中切换；屏幕空间允许时可并排，键盘焦点只归当前选中的棋盘。

## 11. 个人主页与历史记录

第一阶段就建立稳定的公开用户 ID 与个人历史接口，页面可以简单，避免等到个人主页阶段才发现过去只存 PB。

- 基础身份：复用昵称、头像、赞助标识；主页 URL 使用稳定 ID，改名不破坏链接。注册邮箱等私人字段不公开。
- 战绩摘要：四变体各自 PB、最大块、完成局数、有效局数、重开/放弃局数、节点最佳、近期趋势。独立练习局不计入正式战绩；正式局中使用练习不改变统计类别。
- 历史列表：日期、变体、分数、最大块、用时、结束原因、验证状态、完整性、回放入口；采用游标分页，不显示练习使用标签。
- 统计分母：自然完成率与达标率必须说明是否含重开；只统计愿意提交的高分会造成严重偏差。平均/中位数默认按已完成合法同类对局计算，并允许查看全部尝试。
- 默认个人可查看所有归档；公开展示与服务端留存分离。正式上榜局的回放公开是参榜条件；普通历史、练习及未完成局可默认私密。
- 已结束历史和账号统计可以在其他设备查看；“本浏览器进行中”单独从本地存档列出。其他实例的活跃局不提供续玩或加载入口，不能把历史列表做成跨设备存档同步器。未结束服务端证据仅供校验/审核，不通过私人回放下载接口绕过限制。
- 正在进行的局默认不公开实时棋盘/种子/回放，避免旁观喂招；若未来观战，采用明确观战规则和延迟。
- 收藏、备注、精选对局可以后做；全量文件导出要有权限、配额和异步打包，不让一次请求读完全部历史。
- 删除/隐藏主页、注销账号与归档保留应有明确产品政策和技术实现；不能把“全部历史”当成不告知用户的无限期私密行为收集。

## 12. 建议模块与数据模型

在同一仓库扩展独立领域，例如 `frontend/human/index.html`、`frontend/src/human/`、`backend/human_play/`。命名可调整。共享移动内核、账号、棋盘渲染和部分展示组件；对局服务、资格与存储策略独立，避免修改主站历史清理逻辑时互相误伤。

不推荐把整个 Trainer/Gamer 页面拖进新入口：它们带有 AI、固定棋盘和旧排位生命周期。应抽出尺寸参数化纯移动规则、随机接口、记录器与可重用视图，再让旧功能有针对性地回归。

| 实体 | 职责 |
|---|---|
| `human_browser_instances` | 浏览器存储实例的随机标识与账号绑定信息；不保存跨设备续局映射，不视为硬件身份证明 |
| `human_active_slots` | `(user_id, browser_instance_id, variant_id)` 唯一进行中槽，指向 run；原子重开替换，不按账号全局互斥 |
| `human_runs` | 用户、浏览器实例、变体、规则版本、起止时间、结束原因、生命周期、资格、冻结阈值/政策版本、高分状态和越线步；不设练习使用标记 |
| `human_run_leases` 或 run 字段 | 同实例同槽写入 epoch、持有标签页/写入者、高分在线许可期限、最后接收/验证序号；无跨浏览器接管 |
| `human_run_chunks` | 连续范围、内容摘要、前驱、服务端接收时间、存储位置、验证进度 |
| `human_replay_objects` | 不可变归档位置、codec、原始/压缩长度、格式版本、完整性 |
| `human_milestones` | 首达棋块、步号、各时间口径及可信度 |
| `human_verification_events` | 规则验证版本、审核决定、原因、操作者、申诉及修正轨迹 |
| `human_personal_bests` / 榜单快照 | 从有效档案派生、可重建，撤销成绩后可回退到次佳 |
| `human_player_stats` | 可重建聚合，按变体/规则/类别分组 |

生命周期、验证状态、排位资格分列，而不是一个枚举同时承载三层含义：

```text
生命周期：created → active ↔ suspended → sealed
高分监管：local_only → activation_pending → monitored（不可逆）
输入门禁：playable / online_check / network_locked / rollback_rejected
结束原因：game_over / restarted / abandoned / interrupted / expired
验证状态：pending → verifying → verified / invalid / retryable_error
排位资格：eligible / unranked / evidence_gap / under_review / disqualified
```

续玩仅限原浏览器未封局的本地存档，高分局还必须通过重入检查；没有服务端 load/restore。封局后动作日志不可追加，人工审核更改的是资格决定，不改棋谱。公开资料编辑也不重写历史动作。高分输入门禁独立于生命周期：网络锁定不等于封局、失去资格或清除本地状态。

API 建议（仅接口草案）：

```text
POST /api/human/runs                         在本实例变体槽幂等创建/明确重开
POST /api/human/runs/{id}/monitor             首次越线完整前缀上传与高分激活
POST /api/human/runs/{id}/chunks              高分阶段追加二进制动作
POST /api/human/slots/{variant}/reentry-check 验证本实例槽及本地进度，不返回棋盘
POST /api/human/runs/{id}/online-check        高分轻量联网检查，不用于低分定时任务
POST /api/human/runs/{id}/writer              同浏览器同槽切换写入者，不搬运进度
POST /api/human/runs/{id}/seal                全分数阶段补齐回放并原子封局
GET  /api/human/replays/{id}/manifest         已封存历史的只读回放索引
GET  /api/human/replays/{id}/chunks/{chunk}   已封存历史的只读回放块
GET  /api/human/leaderboards                  指定变体/规则/周期
GET  /api/human/players/{id}/runs             分页与隐私过滤
```

低分 seal 可携带完整终局文件或经终局专用分块上传，不能要求它在进行中启用 chunks 周期调用。seal 必须声明最后序号；尾部未齐不得发布“完整回放”。完成事件、PB、统计更新通过幂等事务或 outbox 协调，防止重试重复计数。多个进程部署前必须用数据库约束和事务保证槽位、写入 epoch、序号与唯一终局，不能只靠进程内锁。所有进行中接口验证账号及 browser_instance 归属，账号相同不代表可跨实例续局；API 不存在把服务器棋盘 load 到正式局的路径。

## 13. 运维、性能与验收

归档写入、规则验证、人工复核采用不同限流与调度。每次读取检查所有权/公开资格；不能只依赖随机 replay_id 难猜。带 cookie 的写请求要做明确 Origin/CSRF 校验，新子域应保持 API 同源代理。

可观测指标包括高分监管占比、每高分局请求量、首次越线校验耗时、联网锁定次数/时长、重入校验失败原因、上传成功率、最长未确认尾部、队列等待、每千步验证 CPU、压缩比、每局总存储、日增长、缺失对象、终局至上榜延迟。低分不应产生周期存档或监管心跳请求。日志不要记录令牌、整局重复 JSON 或逐步大段棋盘。

必要验收：

- 四尺寸的合并/计分/出数黄金样本；无效移动、初始两块、矩形行列、方向变换、大块指数、分数上限。
- JS/Python/回放播放器跨实现一致；规则升级后旧回放仍能播放和验证。
- 篡改分数/出数/初始状态、乱序、缺步、重复、冲突前缀、旧 epoch、多标签页同时开局、超长与压缩炸弹输入。
- 同账号同浏览器四变体并存互不覆盖；同变体两个标签页只有一个写入者。相同账号在另一设备/浏览器独立开局互不抢占，不能 load/接管原实例局；规则版本不能绕过同变体单局约束。
- 低分没有周期上传/监管心跳，结束仍完整归档；严格 score == T 与 score > T 的边界、跨阈值后后台上传、实际断网阻断、首次完整前缀上传、阈值政策冻结、高分标记不可回退。
- 高分重入覆盖 L<S、L=S、L>S、同序号不同前缀、本地损坏、ACK 丢失及服务端不可达；正确区分回档拒绝与联网等待，任何分支都不得以云端棋盘覆盖本地。
- 高分断线弹窗与按键/触屏/队列全面锁定；重连校验前不放行，后台返回先锁定，服务端失败不自动降为可离线继续。练习和其他低分变体仍可使用，不能推进被锁正式局。
- 刷新、断网、ACK 丢失、浏览器强杀、本地配额失败、服务器重启、终局重复提交、数据库/对象写入部分失败。
- 长回放随机跳步与从头播放得到相同棋盘、分数和节点；练习 RNG 不改变或复用原局状态；进入练习、练习重开/撤销、返回原局均不改变原局资格或产生辅助标记。
- 所有重开路径使用同一保护；弹窗焦点、移动端触摸、键盘重复、输入框 R、动画期间排队。
- PB 被超越、榜单裁剪、审核撤销、用户改名后旧链接仍然可用，统计可正确重算。
- 私密回放、玩家资料、未结束局不能被其他用户读取；上榜公共内容不泄露审核私密数据。
- 有代表性的并发短局和极长局压测；全量归档备份恢复演练。

## 14. 实施顺序与需要收敛的决策

### 阶段 0：规则与技术验证

冻结 rows×cols、初始与出数规则、时间口径、AI/查表禁止范围、本地暂停/续局政策；允许练习且不标记、浏览器变体隔离、高分门槛联网、服务器只验不加载、暂不服务器出数已经确定。用现有四变体样本验证泛化内核与播放器；采样压缩体积、越线时首次验证耗时及高分周期请求负载，确定各变体阈值和连接检测参数。

### 阶段 1：完整垂直闭环

独立入口与共享登录；四变体独立本地槽和同变体单写入；重开保护；本地完整日志；超过阈值才启用周期增量上传与强制联网；高分重入回档验证且不云恢复；低分终局一次性归档；后端验证；压缩二进制历史；历史列表；节点时间；永久回放链接与跳步；四变体总榜/周榜；进行中和已结束局均可进入独立随机练习，使用练习不影响排位。

没有本地续局、高分重入检查和终局归档闭环，不应先上线“将来再补历史”的人类排位版。服务器恢复玩家进度不属于这个闭环。

### 阶段 2：个人主页与审核工具

战绩聚合、节点 PB、精选对局、隐私设置、导出、人工复核与申诉、异常证据时间线、历史统计回填。玩家页的最小历史功能已经在阶段 1，阶段 2 主要增加展示和分析。

### 阶段 3：需要实测后再扩展

独立速通榜、赛季、日挑战、受监督纪录、延迟观战、归档冷存储。日挑战使用共享种子会改变公平性和重复尝试规则，不能直接并入随机总榜。服务器逐步出数当前不做；跨设备/浏览器共享进行中存档与云端加载也不列入本方案后续阶段。

优先收敛的决策只有以下几项，其余可按本文默认推进：

1. 四种变体各自的高分阈值、监管上传周期、在线检测频率/超时上限；前提已确定为严格超过阈值才周期上传，高分失联锁定，服务器不逐步出数。
2. 节点时间是否采用包含练习、暂停和联网锁定的连续经过时间；建议首版如此，另提供个人分析用的活动会话时间。
3. 同浏览器本地暂停的最长保留期、回档违规的账号处罚政策；不重新讨论跨设备续局或服务器进度覆盖。
4. 全历史是否额外覆盖独立练习会话、默认公开到什么程度；正式局含重开应全量留档，建议仅上榜回放默认公开。
5. 新站名称与子域；不会影响先做规则内核和存档协议。
