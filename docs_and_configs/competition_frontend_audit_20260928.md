# 赛事站大厅与关键流程审计（2026-09-28）

## 范围与方法

本轮检查独立赛事站的大厅、建房、房间导航、实时状态、BP/布阵到正式对局的前端衔接，以及相应后端接口。逐段阅读 `competition/frontend/src/App.vue`、`api.js`、项目目录、后端建房/房间快照/人员权限接口与部署路由；在隔离浏览器中访问已部署测试站，以拦截的假会话/房间响应验证交互。**没有创建或修改线上房间，也没有测试真实六账号并发。** 下表区分“浏览器已复现”和“代码路径确认、尚待时序复现”。

## 覆盖边界与建议修复顺序

现有前端自动化主要覆盖赛事引擎，不覆盖大厅导航、建房表单、正式对局键盘焦点和 HTTP/WS 乱序。此次浏览器用例采用假响应，只能证明前端缺陷；真实账号权限、六席落座、BP 超时、秘密布阵、裁判结算、直播站联动仍需部署环境的多账号端到端回归。不能据此声称这些流程已全部无误或全部有误。

建议按以下顺序实施，并且每一项先补自动化验收：

1. 统一响应式路由与异步请求隔离：大厅 → 房间 → 大厅、创建后跳转、刷新、前进/后退、快速切换房间。
2. 保护正式对局键盘输入焦点；覆盖裁判和队员所有可编辑表单。
3. 建立目录驱动的项目池选择和后端显式 adapter 校验；已创建房间检查是否有意外 `standard-2048-test` 项目，**只报告，不自动改动赛事数据**。
4. 修正棋盘 fallback、单调快照与连接状态。
5. 补工作人员授权、建房向导、房间邀请/在线反馈、列表筛选和直播入口。
6. 做六账号加观众的完整流程回归，包括 BP 两个独立超时、秘密信息隔离、三局结算、断线重连与乱序响应。

本轮审计未修改运行代码、部署或线上数据。
