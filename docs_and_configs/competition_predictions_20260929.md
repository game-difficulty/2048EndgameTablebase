# 赛事直播与固定乘积下注 · 2026-09-29

## 已确认规则

- 两个注题在先后手抽签展示完成、进入公开 BP 时同时开放。
- 首局 A 启动前统一封盘。开放时写入固定的最早开赛时间：开放时间 + 60 秒。
- BP、秘密布阵、就绪可以正常推进；若全部提前完成，在 A 开局检查阶段等待剩余秒数。此时双方包干时钟均停止，不扣用时；到期且双方出战者、队长均就绪时自动启动，无需裁判。
- BP 和就绪超过 60 秒则继续开放，直到实际开赛。60 秒是最低保障，不是自动封盘倒计时。暂停期间不允许下注。
- 全场胜方：黄 / 白，以三名队员显示名组合辨认队伍。
- 前两局黄:白比分：2:0、1:1、0:2。
- 每次 500 / 1,000 / 5,000 / 10,000 Token。每人每题仅一种结果，可追加；每题累计上限 60,000 Token，两题独立。
- 沿用直播现有资金规则，扣常驻 Token，不扣赠送 Token。当前不收手续费；不提供卖出或换边。
- 全场结束才结算两题。全场平局退第一题；A/B 中出现平局而不属于三个比分时退第二题；取消比赛全部退款，结果无法确定则退对应题。

原先“第一题抽签时封盘”及“同一时刻只开一题”不再适用。

## AMM：不是按最终资金池比例瓜分

采用多结果 fixed-product market maker。全场胜方两个选项初始虚拟结果份额储备各为 10,000 Token。前两局比分在两局独立、双方每局胜率相同且没有平局的假设下，2:0 / 1:1 / 0:2 的初始概率权重为 1:2:1；固定乘积 AMM 的价格与储备成反比，因此这三个选项的初始储备分别为 10,000 / 5,000 / 10,000 Token。虚拟份额不记入任何用户钱包。所有资金和份额均用整数 milli-Token（1 Token = 1,000 单位）计算。

购买选项 i，投入 a：

1. 将 a 拆为各结果各 a 份的完整结果集合，加入储备。
2. 其他结果储备 R'_j = R_j + a。
3. 被选结果储备 R'_i = ceil(∏R / ∏(R_j + a), j ≠ i)。
4. 本次获得份额 q = R_i + a - R'_i。

整数取整方向保护乘积不下降。胜出时每份兑付 1 单位，失败兑付 0；每笔 q 成交即锁定，后续订单不改变它。兑付包含本金，不另行返本金。退款时仅返实际投入。

初始边际赔率为全场胜方各 ×2，前两局比分依次为 ×4 / ×2 / ×4，但大额成交存在滑点。例如全场胜方初始投入 1,000 Token 获得 1,909.090 Token 兑付份额，实际赔率约 ×1.909，不是 ×2。新权重用于新市场；旧的等权比分市场只有在仍开放、未成交（revision=0 且无仓位和订单）时才更新，同时递增报价版本以拒绝旧报价。已有下注或已封盘的市场不重置储备，已成交份额与结算逻辑保持不变。

UI 分开展示“当前参考赔率”“本笔成交赔率”“本笔获胜返还”和“已锁定获胜返还”。其他订单导致报价版本变化时拒绝旧报价且不扣款，要求用户核对后重新确认。平台承担虚拟启动储备对应的赔付风险。

数学结构参考：[Gnosis FixedProductMarketMaker](https://github.com/gnosis/conditional-tokens-market-makers/blob/master/contracts/FixedProductMarketMaker.sol)。实现独立，不引入链上合约依赖。

## 数据、并发与故障恢复

- 比赛数据库 schema 9 增加 `competition_prediction_windows`，记录开放、最早开赛和实际封盘时间。封盘与首局状态转换在同一比赛数据库事务内完成。
- 主站钱包库增加独立赛事 markets / positions / orders 表，不改 AI 下注模型。
- 每次新订单向比赛服务鉴权内部接口读取最新许可状态，不采用直播画面缓存作为下注许可。请求在该状态读取处确认是否仍在下注窗口；钱包提交串行化处理，并再次检查市场是否已封盘或收到更新状态。
- 钱包扣款、份额、储备、订单记录在同一 SQLite immediate 事务中提交。每笔 UUID 幂等，超时重试沿用 UUID，不重复扣款；页面刷新后仍能核对未确定订单。
- 状态序号防止过期公开投影覆盖新状态。已封盘市场不可重新开放，已结算市场不可重复派彩。
- 广播异常不改变已成交结果；页面定期读取最新私有仓位。公开广播不包含个人仓位。
- `/api/internal/live/settlement/{public_key}` 保留可结算事实，不受直播大厅结束后保留期限制，仍要求内部鉴权。
- 全局维护任务约每 5 秒检查未结算市场，无观众、进程重启后同样继续结算。比赛服务不可达时暂停新下注，保留已成交仓位并重试结算，不能仅凭网络故障直接判退款。

## 直播功能与界面

- 赛事房间开放现有礼物、红包能力，共用原来的钱包、礼物动画、红包发放领取接口及房间隔离。福袋能力保持关闭，组件也不挂载。
- 独立赛事下注浮窗复用直播活动入口，桌面左右两题，窄屏上下排列。不会调用 AI 下注服务。
- 大厅封面使用双方三人头像、队员名称组合、分列比分、当前项目图标及阶段；比赛标题使用主办方填写的名称。
- 大厅支持中英文切换，语言设置在大厅与房间之间保留。阶段、内置项目名称、比分标签本地化；用户自定义比赛名和队员名保留原文。
- 比赛页及直播开局检查页显示最短下注窗口剩余等待，不与队伍比赛时钟混淆。
