## 房间决定展示区域

`RoomStage.vue` 定义固定 16:9 外框，使用 1280×720 的内容坐标空间。
窗口、手机或小窗尺寸变化时整体缩放；直播内容不能通过自身高度、历史条数、布局切换
改变长方形的长宽。内容类型也不再决定房间的响应式页面布局。
三局内容在该空间内切换主屏／等大模式，历史各自在内部滚动。手机不再变成三局纵向长页。
未来如需改变房间比例，应修改房间容器契约，而不是让某种内容自行扩展外框。

## 从旧验证中保留的逻辑

- `Canvas.captureStream` 生成本地视频轨道，用 video PiP 展示，无需屏幕共享、云端视频编码或上传。

- 处理 enter/leave、播放超时、页面退出、组件卸载和异步开启竞态，停止轨道并移除监听器。
- 验证阶段曾采集全部内容修订；正式界面移除诊断采样，不影响播放与后台连接策略。

没有保留旧组件中绑定 `run/runs` 的窗口生命周期、内容内按钮、随布局变化的画布比例。

## 两种呈现方式

1. **房间小窗（Document PiP）**：房间层把现有 RoomStage 节点移到浏览器置顶窗口，
   复制页面样式和主题，添加房间名称、返回／关闭按钮。原位置显示等比例占位区域。
   不创建第二套 Vue 内容组件，不新建订阅。历史、布局、手动席位状态保留，关闭时将
   同一节点放回原来的位置。新内容只需遵守房间容器契约即可使用，无需实现棋盘绘制器。
2. **兼容视频小窗（Video PiP）**：房间层拥有 canvas、video、MediaStream、绘制节流及清理。
   内容通过 `getPipFrame()` 提供 `{ key, width, height, draw(ctx) }`，不接触浏览器小窗 API。
   2048 的适配器位于 `content/boardPipFrame.js`，固定 960×540；主屏模式含主局和两路预览，
   等大模式含三局，二者都不改变画面比例。兼容模式是观看画面，不能直接操作画面里的控件。

自动模式优先 Document PiP；不支持时，只有浏览器支持 video PiP 且内容提供绘制器才降级。
正式页面可手动选择两种方式。明确失败时显示中英文提示，不自动弹出普通窗口冒充置顶小窗。
房间层不解析任何游戏协议或棋盘数据；未来真人对局、其他游戏、实际视频都可以增加适配器。
视频兼容模式的任意 DOM 截图不属于本方案：没有截图轮询，也不额外请求屏幕共享权限。

## 连接、性能与限制

两种模式都消费原房间状态，网络仍是现有每步增量，既没有第二条观众连接，也没有视频上传。
兼容绘制最多 10 FPS，状态变化合并为最新帧，无变化时最多每秒重绘一次。窗口关闭、页面
退出与卸载均释放资源；改变内容应随 room key 卸载旧房间，不能让旧画面继续播放。
Document PiP 的主题跟随主页面；小窗中历史及切屏直接使用原事件处理器。

Document PiP 需要支持该 API 的浏览器及用户点击；不同浏览器／移动系统的后台冻结策略
仍需实机测试。测试浏览器切换标签后，opener 的 document.hidden 仍报告 false，因此本轮
不将该操作冒充为手机后台冻结验收。未为小窗复制聊天面板、礼物购买面板或单独启动音频。
礼物画面特效作为房间内容舞台的叠加层随 Document PiP 一起移动；兼容视频适配器仅绘制内容。

- 房间维持至少 1500px 的设计宽度，按窗口宽高整体缩放；手机也不把聊天和活动栏挤到内容下方。
