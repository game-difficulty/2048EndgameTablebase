# EXAD 7-Tile Generation Production Plan

## Summary

EXAD generation uses the AD mask, derive, validate, canonical, STSL, and 32k bucket semantics, but stores each layer as AD-slot-partitioned `prefix36 + suffix28` bitmap boardsets. This replaces the legacy AD raw `uint64[]` output and the older EXAD `prefix40 + suffix24 + zero_mask` temporary format for EXAD generation only.

## Data Layout

- Layer file extension: `.exadtmp`.
- LUT file extension: `.exadlut`.
- Outer partition: 48 AD slots for AD keys `-16..31`.
- Per-slot bucket key: `key64 = (prefix36 << 18) | semantic_suffix_sum18`.
- `semantic_suffix_sum18` is the sum of the seven suffix tiles, with masked/placeholder 32768 represented as tile `0xF` and counted as `32768`.
- Fixed 32768 wall cells remain excluded from AD count/sum classification through `AdvancedMaskParam::pos_fixed_32k_mask`.
- Per-slot persisted bucket metadata is AoS `BucketEntry { key, bitmap_offset, dense_offset }`.

## Generation Semantics

- Seed boards are first masked through `FormationAD::mask_board()`, then inserted into AD slots through `ad_bucket_key_for_board()`.
- `ad_bucket_key_for_board()` preserves the old AD classification exactly: normal count32k, negative count32k for pair derive, and `count32k - 3 + 16` for triple derive.
- The generation kernel keeps spawn 2/4, AD move LUTs, pattern filtering, `mask_new_tile`, canonical batch, derive buffering, and derive fixed-array output.
- Plain boards insert directly into the target carry layer.
- Derived boards are generated by `derive()` and then inserted; derived outputs are not used to deduplicate base-board hash candidates.
- `arr1` reuses the previous step's `next_seed_carry`; `arr2` becomes the next `next_seed_carry`.

## Validate And Resume

- STSL validate condition follows legacy AD:
  `((step + int(ini_board_sum % 64 / 2)) % 32) == ((int(stsl / 2)) % 32) + 1`.
- When validate triggers, the finalized current layer is filtered at `board_sum + 2`; the in-memory next carry is finalized, filtered at `board_sum + 4`, and rebuilt as carry.
- Resume prefers consecutive `.exadtmp` files: `step-1` becomes current and `step` becomes next seed carry.
- Old EXAD 6tile files are intentionally incompatible with the new magic and must be rebuilt.

## Statistics

`exad_generate_stats.csv` records:

`stage,step,input_live,arr1_live,arr2_live,output_live,derive_candidate_count,derived_output_count,validate_removed_current,validate_removed_next,prepare_seconds,generate_seconds,insert_seconds,finalize_seconds,validate_seconds,write_seconds,retry_count,compute_seconds,total_seconds,compute_throughput_mbps,time`

`compute_seconds` excludes file IO and includes prepare, generate/insert, finalize, and validate.
