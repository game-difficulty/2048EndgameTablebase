## 启动与停止

在项目根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File tools/start_human_local.ps1
# 已构建前端时可跳过构建
powershell -ExecutionPolicy Bypass -File tools/start_human_local.ps1 -SkipBuild
# 停止本脚本启动的服务
powershell -ExecutionPolicy Bypass -File tools/start_human_local.ps1 -Stop
```

默认 Python 为 `C:/Anaconda/python.exe`，可用 `-Python` 指定；可用 `-Port` 指定端口。需要已安装项目 Python 依赖及 `frontend/node_modules`。脚本检查已运行的进程和端口，不终止其他服务；后台服务隐藏运行。

打开页面，点击“登录 / 体验”→“使用本地体验账号”。此账号只在本地预览数据库中创建。未登录可以玩访客练习，不进入排行榜。正式账号验证复用主站 auth 模块；预览没有连接线上账号库。

本地数据与日志在 `tmp/human-local/`：

- `auth.sqlite3`：预览账号与会话。
- `human.sqlite3`：对局元数据、校验进度、证据、压缩回放与审核事件。
- `server.pid`、`server.log`、`server.err.log`：服务进程与日志。
- 浏览器 IndexedDB `human-play-v1`：此浏览器独立的原局状态、全部动作、本地归档待上传队列。

请固定使用同一地址。`localhost` 和 `127.0.0.1`，以及不同端口、浏览器配置文件，是不同的浏览器存储空间，不共享进行中存档。不要将预览数据库当作生产数据库。

## 已实现

- 四变体（行 × 列）：4×4、3×4、2×4、3×3；初始两块，90% 出 2、10% 出 4，预生成种子，前端本地确定性出数。
- 同账号同浏览器每变体一个进行中槽；Web Locks 保证同变体单标签页写入，数据库唯一索引与 writer epoch 二次约束。各变体和各浏览器独立。
- 每步状态与动作通过同一 IndexedDB 事务提交；刷新后从本地继续。服务器状态接口不返回棋盘、RNG 或动作，不提供正式局云恢复接口。
- 左侧首次达成节点用时（纯展示，无点击跳转）；计时从首个有效移动开始，包含练习、暂停和离开页面的间隔。计时是客户端报告值，未作为独立速通榜资格依据。
- 高分越线即时后台监管；有新增动作时每 20 秒或累计 32 步追加上传（先到为准）；空闲高分局每 5 秒轻量联网检查；12 秒连接许可，按请求起点计时并预留 0.5 秒；隐藏页面尝试 keepalive 留档，返回后台校验。首次联网/重入在 8 秒单请求确认窗口内可继续操作，实际断网、失败、超时或验证不通过才阻断。
- 断线在棋盘上显示阻断弹层，正式局键盘与触屏动作均锁定；练习仍可继续。浏览器断网事件即时触发，服务不可达以请求失败/许可过期检测，不声称能瞬时识别所有链路故障。
- 高分重入检查本地序号不小于服务端且前缀一致；本地领先补传尾部，本地落后判回档、保存审核事件并拒绝继续。全程不会用服务器状态覆盖本地。
- 低分没有监管心跳或周期动作上传；低分死亡时完整上传归档；低分重开、放弃等非自然结束只保留本地回放，不发起归档请求，也不进入后续补传。初始开局和重入获取写入权仍需接口请求，已开始的低分局可离线移动。
- 后端逐步重演、校验种子出数/合法移动/哈希前缀/序号/写入者，独立全量重演后封存；成绩由后端计算。自然结束且验证通过自动进入分变体总榜、周榜；非自然结束的记录只能由站长审核后手动准入。每人取最佳，同分同名次。
- 自己的历史列表、基础玩家页、最佳成绩、归档数量与分页；他人可查看自动上榜或站长手动准入的记录及回放。其他重开／中断记录仅本人可见。
- 所有自然结束、以及得分严格超过本局变体高分阈值的非自然结束正式局上传压缩二进制回放，不按榜单名次删除；等于阈值的非自然结束局不上传。高分重开等非自然结束局上传失败后仅静默待补传，不显示弹窗或顶部归档失败提示；重开保护不变。死亡局的失败弹窗和补传提示保留。无法恢复本地丢失的未上传尾部，违规或损坏记录保留服务端已有证据。
- 回放播放、变速、任意步跳转、分享步号链接与下载；每 256 步建立浏览器内快照辅助跳步。
- 随时从当前正式局或回放任意步进入独立练习；随机出数、手动出数、摆盘、清空、撤销/重做。练习不继承种子、不提供 AI/查表、不标记辅助、不影响原局资格。
- 得分达到重开保护线，或已经是高分监管局时，按钮与 R 键共用确认弹窗，默认焦点为“继续本局”。

| 3×4 | 70,000 | 2,500 |

## 首版代码与协议

前端独立 Vite 入口：`frontend/human/index.html`，实现位于 `frontend/src/human/`。后端位于 `backend/human_play/`。主应用只增加路由注册与数据库初始化，预览使用 `backend.human_play.local_app:app`，不启动 AI、直播或对战后台任务。本地体验登录接口仅存在于此回环预览应用，不注册到主应用。

实际 API 与设计草案中的候选路径有收敛：

```text
GET  /api/human/config
POST /api/human/runs
GET  /api/human/runs/{id}/status        仅序号、前缀哈希、资格、许可等元数据
POST /api/human/runs/{id}/writer        低分重入获取写入权，不上传动作
POST /api/human/runs/{id}/monitor       首次越线
POST /api/human/runs/{id}/append        高分增量
POST /api/human/runs/{id}/reentry       高分重入验证及补尾部
POST /api/human/runs/{id}/online-check  高分轻量联网检查
POST /api/human/runs/{id}/seal          封局
GET  /api/human/replays/{id}            仅封存回放
GET  /api/human/leaderboards
GET  /api/human/players/{id}            基础资料、统计与分页历史
```

HPR1 文件：4 字节魔数 + uint32 LE 头长度 + 小型 JSON 版本/种子头 + 二进制动作。每步固定 5 字节：1 字节方向/出数位置/2或4标志，4 字节 uint32 LE 毫秒间隔。服务器使用 gzip level 6 压缩存入 SQLite BLOB，已移除冗余的归档文件 SHA-256，保留 gzip CRC32/长度与完整规则复算；上传按完整动作边界追加，每块校验前缀哈希和幂等性。下载使用 HTTP gzip，浏览器保存解压后的 `.hpr` 二进制文件。单局上限 200,000 步。

联网时监测、验证、上传和历史补传不持有棋盘输入锁。回执与走棋的本地事务串行，回执只合并确认元数据；发送快照与重入前的本地序号被冻结，迟到回执不会覆盖新棋盘，验证期间新增步数也不能掩盖回档。旧回放封存不再挡住重开和历史页显示。详见 [后台同步与资源评估](human_play_resources.md)。

这是首版协议，尚未实现设计草案中的 varint、对象存储、分块下载、异步验证队列与冷存储。封存时的全量验证在工作线程和数据库事务内执行，正式上线前需要长局和并发压测，再决定队列与存储拆分。

## 站长手动准入

目前提供仅能由持有数据库访问权限的站长使用的命令行工具，没有玩家端核准 API 或审核网页。先核实丢档等原因，使用 `inspect` 查看服务器留存步数、哈希、验证事件和审核历史。以下命令在项目根目录运行，替换对局 ID、步数与哈希：

```powershell
& C:/Anaconda/python.exe -m backend.human_play.admin --db tmp/human-local/human.sqlite3 inspect RUN_ID
& C:/Anaconda/python.exe -m backend.human_play.admin --db tmp/human-local/human.sqlite3 approve RUN_ID --operator webmaster --note "本地丢档，已核实留存进度" --expected-seq 1234 --expected-hash PREFIX_HASH
& C:/Anaconda/python.exe -m backend.human_play.admin --db tmp/human-local/human.sqlite3 revoke RUN_ID --operator webmaster --note "撤销原因"
```

- 核准前要求步数和哈希与查看时一致；进度变化时必须重新查看。从初始种子全量重演已留存动作，核对完整状态与分块／归档完整性，不允许手填成绩。
- 未封局的临时留档在最后留存一步封存为 `interrupted`（已有 `restarted` 原因则保留），停止追加并生成压缩二进制回放；不会冒充自然死亡、恢复或覆盖玩家本地棋盘。没有动作的记录不能核准。
- 既有完整归档只变更排名准入，不修改棋谱和结束原因。验证已判失格的局不会通过此工具恢复资格；申诉仍需后续单独设计。
- 核准同步影响总榜、周榜、个人最佳、公开历史和回放权限。未封存记录按最后一批有效动作的服务器接收时间归周，已封存记录保留原结束时间，审核日期不改变周归属。
- 每次核准／撤销保存操作者、原因、时间和证据步数／哈希，审核细节不公开。撤销后重新计算榜单与个人最佳，回放仍留存并对本人可见，已封存局不会重新开放续玩。

## 2026-10-03 辅助行为待审

- 主站仅记录手动 setboard 后的首次 AI 求解，以及练习页手动 setboard/摆盘触发且有数值结果的主查询。连续 AI、预取、测试/回放跳转不记录。并列一选固定按 left/right/up/down 排序。
