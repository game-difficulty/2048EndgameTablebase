# 比赛站移动端视图与操作方案（2026-09-29）

状态：设计稿，尚未实现。范围是 `tournament.2048tables.online` 的比赛大厅和选手房间；直播站维持独立的观众布局。目标是让手机完成落座、队长 BP 与布阵、出战操作、结果确认，而不是把手机限制为只读设备。

## 1. 核心取舍

1. **出战者优先看自己的完整棋盘。** 黄、白双方公开棋盘仍可随时查看，但手机竖屏不强制同时展示两个完整棋盘。自己的棋盘永远是默认主视图，屏幕下方保留对方成绩与状态入口；点一下即可查看对方完整棋盘，再点一下返回。切换不改变后台计时或输入权限。
2. **本场状态常驻，历史与说明按需展开。** 顶部保留系列比分、双方包干时间、当前项目图标；棋盘上方仅有成绩指标和项目用时/倒计时。项目规则通过图标或“规则”入口展开，其他两场的详情不占用对局高度。
3. **每阶段只突出一个提交动作。** 可逆的选择不弹确认；不可逆的 BP 锁定、布阵提交、退出正在对局的页面须显示简短核对。报告问题独立于常用操作，不悬浮盖住棋盘。
4. **移动输入必须与桌面同语义、同速度。** 滑动与方向按钮只是同一 `move` 命令的两种入口，不能因手机端先等动画或网络回包而降速。对抗出数 AI 思考期间仍遵循项目自身的输入锁定。
5. **服务端是状态和计时权威。** 本地倒计时仅用于平滑显示；超时、完成、胜负、阶段切换以服务端确认为准。刷新、切到后台、旋转屏幕后恢复当前阶段，不重置棋盘或截止时间。

## 2. 当前实现与主要缺口

- 棋盘组件已有 Pointer Event 四向滑动、18 CSS px 判定和 `touch-action: none`。这部分可复用；只有本人棋盘可输入。
- 当前手机赛中页把黄、白两个完整棋盘纵向排列。白方出战者必须滚到第二盘才能操作；对局期间滚动也会使上方时钟离开视线。
- 赛中方向按钮为 38×34 px，低于手机可靠触控尺寸；“问题上报”浮动入口有遮挡棋盘的风险。
- BP 项目池在窄屏降为单列，项目多时锁定按钮离当前选择很远；独立倒计时也可能滚出视线。
- 当前 `moveGame` 在 `movePending` 期间拒绝后续输入。此逻辑在高延迟移动网络下会直接吞掉快速操作，是竞速项目移动端上线前必须解决的输入链路问题，不属于单纯的 CSS 调整。

## 3. 手机公共外壳

适配基准：320–430 CSS px 竖屏；431–767 px 使用同一结构并增加留白；横屏不要求旋转，若横屏有效高度低于 440 px，切为低顶栏的聚焦视图。布局按 `visualViewport` 和安全区计算，不把浏览器地址栏高度视为永久可用。

| 区域 | 常驻内容 | 行为 |
| --- | --- | --- |
| 顶部比赛条 | 黄/白系列比分、两队包干时间、项目图标/字母、连接状态 | `position: sticky`；点项目图标打开规则与赛程；不重复展示队长姓名 |
| 阶段信息 | 当前行动方、本队独立剩余时间、对方“选择中/已提交”等公开状态 | BP/布阵时紧贴顶部；比赛中不显示冗长阶段条 |
| 主舞台 | 当前阶段唯一核心内容 | 出战者是本人棋盘；队长 BP 是项目池；布阵是 A/B/C 选择；候场者是只读双盘 |
| 底部操作区 | 当前阶段唯一主按钮；对局时是方向输入和必要的项目动作 | 贴合底部安全区；键盘弹出或弹层出现时不遮挡提交按钮 |

常规触点至少 44×44 CSS px，方向按钮建议 48×48 px。文字与颜色共同表达黄白、已提交、可操作等状态。深色模式使用比赛站现有暖底/深蓝与黄白队伍色，不另外建立一套视觉语言。

## 4. 分阶段视图

| 阶段 | 选手手机主视图 | 队长或出战者操作 | 其他人所见 |
| --- | --- | --- | --- |
| 大厅、落座 | 房间码/人数；黄、白分段切换，各 3 个席位；1 号明确标“队长” | 点空位落座；本人席位显示离席。关闭房间仅主办方在更多菜单中操作 | 每席头像、姓名、准备状态 |
| 队长准备、抽签 | 六人状态、两个队长准备状态；抽签结果大字揭示 | 队长底部“准备/取消准备”；抽签无需人工启动 | 不出现无权按钮 |
| 公开 BP | 顶部固定本队剩余时间、先/后手和已锁定 A/B/M/N；项目池两列图标卡 | 顶部分段“选择 / BAN”；点卡设置对应候选，卡上的“规则”打开详情；底部固定候选摘要与“锁定并公开” | 卡片只读，仍显示合法池和公开进度 |
| 盲选 | 两列项目池和本队候选；对方仅显示“选择中/已提交” | 点卡选 X/Y，底部“密封提交” | 对方候选值在揭晓前绝不下发至浏览器 |
| 秘密布阵 | A/B/C 三行：项目图标、项目名、当前选择的本队头像；顶部本队 3 分钟倒计时 | 点一行打开本队三人选择层；重复选人就地提示；底部固定“提交布阵”并核对一次 | 本队队员可见本队已提交安排；对方只见密封状态 |
| 开局检查 | 当前项目大图标与简短规则、自己/本队需要完成的就绪项、双方公开就绪进度 | 出战者“已就绪”，队长“确认开局”；双方齐备自动开局 | 不提前揭示未开赛场次的对方出战安排 |
| 项目对局 | 出战者：本方成绩与时间、最大可用本人棋盘、对方成绩状态条；队长/队员：只读双盘切换 | 棋盘滑动或底部方向键；撤销在支持项目中显露，重开在次级菜单中二次确认 | 两队所有选手均可点“看对方”检查公开棋盘，但对方画面不接收输入 |
| 单方完成、单局结果 | 完成方显示“服务端已确认”，本队时间暂停，对方棋盘可作为主视图；结果页展示两人成绩/胜方 | 队长底部“确认结果”；出战者不可继续移动 | 双方确认状态公开，下一项目名称可见 |
| 全场结算 | 获胜方与总比分；A/B/C 三行图标、双方出战头像及成绩 | 返回大厅 | 同信息只读 |

## 5. 出战者对局画面与输入

竖屏推荐结构：

```text
┌ 黄局分  余时  │ 项目图标 │ 余时  白局分 ┐  ← 固定比赛条
├ 我的成绩                         项目用时 ┤
│                                            │
│               本人完整棋盘                 │
│                                            │
├ 对方：成绩 / 用时 / 进行中       [看对方] ┤
├ [撤销※]      [↑] [←] [↓] [→]           ┤  ← 底部安全区
└ [规则] [报告问题] 置于菜单或抽屉，不盖棋盘 ┘
```

`※` 仅支持撤销的项目显示。操作区可提供“手势优先 / 显示方向键”偏好，但无论偏好如何，棋盘滑动都保持有效。重开不与撤销/方向键贴邻，避免误触。仅本人正在对局的棋盘响应滑动；切到对方棋盘时方向键隐藏或禁用，并显示“对手棋盘·仅供观看”。从对方视图返回本人棋盘只需一次点击，不能靠浏览器后退。

棋盘按**可用高度**而非仅按屏宽定尺寸：正方形项目 `side = min(屏宽-16px, 可用高度)`；真华容道的完整入口—棋盘—出口舞台维持 4:7，`width = min(屏宽-16px, 可用高度×4/7)`。不使用整体 `transform: scale()` 缩小控件与文字。320×568 机型可以隐藏对手缩略图，但对手成绩条与完整查看入口不可消失。较高屏幕可在对手成绩条下显示约 120–160 px 的只读缩略盘；缩略盘绝不拦截本人棋盘滑动。

输入事件约束：单指主指针、轴向锁定、短距离误触过滤、指针取消清理；触控滑动只在棋盘区域阻止页面滚动。方向按钮与手势共用相同限流/序号逻辑。普通项目应本地立即推进确定性棋盘动画，并按顺序向服务端提交 `input_seq`，服务端回执用于校验与纠偏；不能把“请求未返回”作为下一次输入的统一阻塞条件。若某项目确需服务端计算（如对抗出数），只在该项目的思考窗口显式锁定输入并显示“思考中”。这是移动端竞速可用性的前置实现任务。

## 6. 候场与观战中的队员

未出战选手不显示方向操作。主区默认展示两队公开棋盘：正方形项目可上下排列并支持点任一盘放大；真华容道优先显示两队成绩/倒计时条与一个主盘，另一盘一键切换。队员切换不会影响出战者状态。任何队员都可随时看到对手进度，遵守既有公开投影，不向前端额外发送秘密布阵或盲选内容。

## 7. 异常与可访问性

- 网络断开时保留最后服务端棋盘，显示“重连中”和最后同步时间，立即禁止新输入；队伍包干时间仍按服务器状态展示，不暗示暂停。
- 应用切后台恢复时重新取快照并校时；本地未确认输入须按序号核对，不能盲目重放。
- `prefers-reduced-motion` 关闭阶段转场与装饰动画，但不改变游戏输入判定。
- 动态计时不逐秒向屏幕阅读器播报，只在 10 秒、5 秒、超时提示。所有项目卡、席位、按钮有可读名称和明确焦点态。
- 报告问题表单为底部抽屉，开启后冻结本地输入焦点但**不自动暂停比赛**；是否暂停仍由后端规则/裁判处置。

## 8. 交付顺序与验收

1. 移动公共外壳、落座/BP/布阵的固定计时与提交区。
2. 赛中本人棋盘优先、对方一键切换、限高几何、48 px 方向键和安全区。
3. 解决 `movePending` 吞输入：立即本地执行、序号提交、服务端校验；对抗出数保留专用等待状态。
4. 候场/结果/结算及断线恢复。

至少在 iOS Safari 与 Android Chrome 测试 320×568、390×844、430×932 和 844×390；覆盖黄/白双方出战、12 项目 BP、三项目布阵、3×3/5×5/随机形状/4:7 华容道棋盘、撤销/重开、单方先完成、连接中断与系统字体放大。验收条件不是“页面不溢出”，而是无需缩放和横向滚动即可完成所有被授权的手机操作，并能在一次点击内查看对方完整公开棋盘。
