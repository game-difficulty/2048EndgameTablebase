# 主站与定式站入口拆分

状态：本地实现与验证完成，待提交和部署。范围：前端与上线配置准备，不在本次实施中提交或部署生产。

## 1. 目标和边界

- 新增 `https://tables.2048tables.online/`，承载训练、测试、定式对战、定式回放、批量分析、设置。
- 复用主站应用外壳、组件、账号、权限、额度和后端，不复制业务实现或新建数据库。
- 主站首页改为两行三列：开始游戏、定式、小游戏；2048 AI、设置、帮助。
- 定式站首页两行三列：训练、测试、对战；回放、分析、设置。
- 独立回放播放器 `/verse-replay/` 保留在主站，不与定式回放页混淆。
- 主题、语言、配色、字号、动画等沿用现有账号同步。演示速度、出4概率及其他未同步字段继续按域名保存，不新增同步字段或游客同步协议。
- 不为历史外链保留两套页面或协议，但更新当前网站生成的所有相关跳转。已有且无需额外代码的链接行为不主动破坏。

## 2. 构建与站点配置

- Vite 新增 tables HTML 入口，与 main/live/human 同批构建；独立的薄启动模块复用 App.vue。
- 集中的站点配置定义站点标识、首页条目、定式页面归属、外部地址和深链接生成。
- 生产由域名/HTML 入口确定站点；本地通过 `/tables/` 入口预览，不依赖伪造公网域名。
- 两站使用同一后端 API/WebSocket；生产通过各域名同源代理，保留父域 HttpOnly 会话 Cookie。
- 不修改比赛站业务、不修改直播间内容、不修改 AI 或定式查询算法。

## 3. 导航与 Tab

- 顶栏拆为首页按钮、可滚动的工作 Tab 区、不可收缩的固定入口区。
- 首页为独立图标按钮，不占工作 Tab；关闭最后一个工作 Tab 后回到首页。
- 右侧固定为直播大厅、赛事大厅、账号菜单。两站共用。
- 直播打开 `https://live.2048tables.online/lobby`，赛事打开赛事站大厅；外站链接新窗口打开。
- 直播动效以大厅存在正在直播的房间为准，不只检测 AI 直播；后台停止轮询，失败不显示错误的“正在直播”。
- 当前站内页面复用 Tab，不重复创建；定式站提供返回主站入口。
- 主站帮助/AI 等发起训练、测试、定式回放、分析跳转时，送至定式站。携带盘面等上下文的跳转保留上下文，不只跳首页。
- 定式站中训练停靠、测试到训练、回放到训练继续本地运行，保持原快捷键和焦点归属。
- 不把文件数据或登录令牌放进 URL；带文件的跨窗口传递只允许已知站点来源、原始 opener、一次性消息令牌及大小限制。

## 4. 分析页面

- 把分析组件改为可嵌入页面的共用内容；用 embedded 属性区分页面/浮窗外壳，不复制分析逻辑。主站外壳不再挂载隐藏的旧分析浮窗。
- 新增 Analysis Tab；完整使用工作区，不使用全屏遮罩/teleport，不阻挡其他 Tab。
- 内含批量分析、分析历史、刷新历史、任务进度、阶段回放入口。
- 切换 Tab 仅隐藏页面，不销毁任务状态、不重复提交、不重置选项；运行中继续同步状态。
- 真正关闭 Tab 断开前端轮询/连接，但不取消后端任务；重新打开恢复保存的任务。
- 新文件上下文在同一分析 Tab 处理，运行期间不得覆盖当前任务输入；需要给出明确提示。
- 标题栏可见；输入、结果、历史区域 min-height:0 和可滚动，避免固定行高遮挡。

## 5. 站内跳转审计

- 主站首页、更多、帮助、排行榜、游戏页、测试和回放组件的 navigate-tab。
- 对战房间邀请地址以当前定式站 URL 生成。
- 分析历史和分析完成后的回放 open-link：服务端生成地址使用新的定式站配置。
- Play 站/其他入口的分析文件跨窗口消息握手；使用精确源校验，不允许 `*`。
- 保持独立回放播放器、Play、直播和赛事的现有地址，不做全站域名字符串替换。
- 新 URL 只维护一种参数协议；解析时只接受登记的页面和必要的上下文字段。

## 6. 设置与数据

- 复用 SettingsPage/useAppSettings/accountPreferences，账号同步白名单不变。
- localStorage 天然按来源隔离，定式站本地参数首次使用默认值，这是预期行为。
- 登录用户首次访问仍由共享会话识别账号并加载已有偏好；复用现有防闪烁与重试机制。
- 不迁移历史本地任务缓存、游客身份、打开的 Tab、训练停靠偏好；服务器分析历史不受影响。
- 日活统计纳入 tables 来源，仍使用统一认证记录机制，不在功能接口中散布计数。

## 7. 视觉与兼容性

- 沿用当前主页卡片的颜色、图标容器、字体、悬停与明暗主题，只调整布局与条目。
- 六入口固定三列两行，沿用现有整体缩放策略。
- 顶栏只有工作 Tab 滚动，固定链接与账号不会被挤出；中英文字不换行。
- 新页面继续加载已有兼容检测及兼容样式；检查构建脚本是否覆盖新增入口。
- 首屏不新增说明型大段文案；网站名称体现“定式”。

## 8. 测试与验收

1. 单测：两站首页条目、Tab 归属、URL/上下文往返、来源校验、直播大厅状态。
2. 单测：分析嵌入与弹窗生命周期、切换保留任务、不覆盖运行中的输入。
3. 回归：原 Tab 排序关闭、训练停靠、分析恢复、账号偏好测试。
4. 构建：主站/live/Play/tables 同批编译，tables 入口与兼容 CSS 均输出。
5. 浏览器：两首页六入口、固定右侧导航、多 Tab 滚动、分析/历史滚动、明暗主题、中英文、窄屏缩放。
6. 网络：登录/游客访问、设置加载、API/WS 地址、站内跨域跳转与文件握手。

## 9. 部署准备与回滚

- 本次仅准备代码与配置，不自动发布。
- 发布前遵守 AGENTS.md 和 deployment_retention.md，核对线上基线，禁止使用脏工作区构建。
- DNS 新增 tables；证书包含新域名；Nginx 使用本批 frontend/dist 的 tables/index.html 回退，并代理现有 API/WS 和分析下载资源。
- 分析链接由 backend/analysis_history.py 统一生成，已改为 tables 域名；必须同步发布使用该模块的 Play 分析后端，否则页面仍会收到旧域名链接。
- Nginx 模板已将 tables 加入主站的 server_name，共用现有 API/分析/WS 分流；backend/app.py 按 Host 选择 tables/index.html。生产若采用静态直出配置，需把同一规则落实到实际 vhost，不能直接覆盖不同结构的线上配置。
- 上线后检查主站、tables、live、Play 资源批次和内部跳转；不改比赛站构建，仅使用其大厅链接。
- 回滚切回上一个前端批次并恢复分析链接配置；无数据库破坏性迁移。
