# 2048 社区前端版面设计与实施

日期：2026-10-03。以功能提交 `6ee17d5` 为基线，根据现有可用功能重排页面。此文描述已落地的布局；完整首版的功能缺项继续以 [验收清单](../../forum/ACCEPTANCE.md) 为准。

## 1. 页面组织原则

社区的主要任务是发现讨论、阅读局面、交流思路和发布内容。首页优先展示讨论列表；棋盘、图片、录像在正文中呈现；个人事务和管理事务分别进入独立工作区。

采用暖灰背景、浅色纸面和棕金强调色，深色模式使用低亮度灰绿背景。主题标题、正文和棋盘具有最高视觉优先级，标签、时间、统计和管理操作降低权重。保留系统/浅色/深色选择。棋盘继续读取共享的主站 tilePalette，页面配色不覆盖方块背景。

## 2. 全局导航与响应式

| 区域 | 内容与安排 |
| --- | --- |
| 顶栏 | 社区标识、主站/Play/直播/赛事入口、全站搜索、外观选择、个人页入口 |
| 桌面侧栏 | 发布主题；全部讨论与六板块；通知、收藏、我的社区、偏好与隐私；按权限显示管理入口 |
| 页面主体 | 面包屑式上下文、页面标题、简短说明、当前页核心操作；其后才是内容和工具 |
| 手机导航 | 页首板块选择，底部讨论/创作/通知/我的四入口；跨站导航仍保留在顶栏第二行 |

最大页面宽度 1560px，桌面侧栏 212px；900px 以下收为 184px。700px 以下隐藏侧栏和顶栏搜索，以页面搜索和底部导航承接。底部保留安全区与滚动留白，防止末尾操作被固定导航遮住。侧栏可在视口内独立滚动，使较矮屏幕仍可访问管理入口。

首页与创作页在 1190px 以下将辅助栏移到主体下方；运营页在 1100px 以下上下排列。设置页在 900px 以下单列。断点按内容空间选择，各页无需强行使用相同栏数。

## 3. 首页、板块与收藏

桌面主体由“讨论列表＋260px 辅助栏”组成。内容顺序如下：

1. 板块/页面标题、说明和板块订阅。
2. 最新公告横条，提供直接进入公告的链接。
3. 最新回复、最新发布、精选、未回复、关注、未读视图；后两项仅登录可用。
4. 搜索输入和可折叠高级筛选：标签、作者、主题 ID、类型、开始/结束时间。
5. 主题列表与继续加载，每行突出标题，其后显示类型/状态、作者、时间、标签和回复数量。

辅助栏放创作入口、棋盘语法示例、公告和真实来源动态；不存在的数据不填充假排行榜或在线人数。手机端将辅助内容放在列表之后，隐藏重复的创作引导卡，保留语法帮助。

筛选提交后同步到 URL，刷新或再次打开链接可恢复搜索条件；标签可以直接筛选。清空筛选保留当前视图。空列表区分暂无讨论和无匹配结果。该实现不等于分页列表的返回位置恢复，后者仍在待办范围。

## 4. 主题阅读与回复

阅读区最大宽度 1000px，正文控制在 760px 内。标题、板块/标签和主题动作集中在页首；管理动作收进单独折叠区。阅读工具条放只看楼主与回复入口。

每个楼层独立成卡，顺序为作者/楼层/时间、正文、主题扩展、互动操作。投票和问答状态放在首帖正文后，读者先了解上下文再参与；分页未加载首帖时，扩展区仍可单独访问。正文继续承载棋盘、媒体和回放，不拆成互相割裂的页面。

回复编辑器放在楼层列表下方并提供锚点。点赞、引用、编辑、举报等按原有权限展示，既有阅读标记、回复草稿、修订历史与录像交互沿用。

## 5. 创作台

桌面左侧是标题与正文，右侧 280px 栏是发布设置和提交操作。把持续书写和偶尔调整的元信息分开，减少编辑时来回寻找输入区。

- 写作区：标题、正文、棋盘语法速查、Markdown 工具、图片/录像、提及、棋盘即时预览；手绘保留为可选辅助。
- 设置区：板块、主题类型、标签；只有选择投票时才展开选项、截止时间、最大选择数与结果显示规则。
- 提交区：来源提示、草稿保存状态、发布、保存草稿。设置字段仍在同一表单内，必填截止时间参与浏览器校验。
- 顶部：预览/继续编辑，以及可展开的云端草稿。预览采用正式正文渲染器，棋盘与发布后保持一致。

窄屏依次排列写作、发布设置、提交区。保留自动保存、冲突对照和原有发布去重，不用版面调整改变数据语义。

## 6. 个人区、通知和设置

“我的社区”默认打开继续阅读，并以页签切换回复草稿、关注与订阅、附件、申诉，避免将五组独立事务堆成一条长页。草稿页同时提供主题草稿入口，各组保留原有管理操作。公开用户页由顶栏头像进入，私有收藏可从侧栏或“我的社区”页首进入，手机端同样可达。

通知页保留分类、实时连接状态、暂停接收和全部已读；消息以卡片展示，未读有文字标识和强调边线。设置页分为通知偏好、屏蔽、数据与隐私三块；桌面前两块并列，数据区占整行。原有加载期间禁止写入和请求失败提示保持有效。

## 7. 管理工作台

内容治理与运营分别进入页面，顶部互相链接。普通用户导航中不出现管理入口。

| 页面 | 工作区 | 布局 |
| --- | --- | --- |
| 内容与审核 | 举报、申诉、主题、审计、权限、板块、附件、通知任务 | 横向功能页签，下面只展示当前任务；窄屏页签可横向滚动 |
| 公告与运营 | 定时公告、赛事/直播来源动态、隐私请求 | 公告/来源采用左侧编辑、右侧记录；隐私请求使用全宽记录区 |
| 运行信息 | 服务状态与队列指标 | 默认折叠，需要排障时展开 |

公告记录保留状态、版本、时间和相应动作。跨站摘要是否已被目标站消费、工单结案是否实际完成删除，继续用现有说明明确区分，不以新界面暗示未实现的自动处理。

## 8. 可访问性与维护

增加跳到主要内容入口；页面与导航具有可读名称；仅装饰的符号对辅助技术隐藏。页签按钮通过 aria-pressed 表达选中状态，折叠使用原生 details/summary。手机隐藏用户名时，头像链接仍有完整名称。触屏的页签和主要楼层动作保留至少 44px 的点击高度。

布局样式放在 `forum/frontend/src/layout.css`，在基础样式之后加载；基础控件、正文渲染和棋盘规则继续使用原组件。页面入口和功能权限不依赖 CSS 隐藏保障，后端校验继续生效。屏幕阅读器全流程与对比度专项审计仍需后续完成。
