# 云端盘面和目标接入

## 范围与语义

本次接入现有结果的云端查表、训练、测试、回放分析和 Play 归档分析，不在云端增加计算入口。
目标身份使用 `sum-1800` / `sum-900`；完整定式标识为 `3x3_sum-1800` / `2x4_sum-900`。
旧数字目标、旧文件名与存储目录保持兼容。

盘面和目标允许 4–16382 的偶数。仅在移动有效且仍满足定式时，移动后的编码盘面总和对 16384 取余，达到目标减 2 即成功。下一次出数至少为 2，因此该判定与约定一致；不可移动的满盘不能直接判胜。内部取余自然排除 16384 / 32768。概率为 1 本身不代表已经达标。

`GoalSpec` 分离目标标识、成功条件和编码上限。Classic、EX、BC Reader 在合法移动后执行该判定；EX 仍使用原 zlut 解码，BC 保留固定 16384 的编码能力。AD / EXAD 不接受盘面和目标。新增 `TableGoal.h`，部署必须同时重新编译 native Reader，不能只更新 Python。

## 表库配置

`docs_and_configs/cloud_tablebases.json` 已登记以下本地服务器目录，默认根目录 `/opt/2048tables/tablebases`：

| 本机源目录 | 服务器相对目录 | 目标 | 类型 / 出4概率 |
| --- | --- | --- | --- |
| `C:/2048_tables/cloud tables/3x3_sum-1800_ex` | `3x3_sum-1800_ex` | 盘面和1800 | float64 / 0.1 |
| `C:/2048_tables/cloud tables/2x4_sum-900_ex` | `2x4_sum-900_ex` | 盘面和900 | float64 / 0.1 |

复制时保留全部 `.zbook`、`.zlut`、`goal.json` 和现有文件前缀，不把文件改名为普通数字目标。目录尚未存在时不会出现在可用目录中；数据落盘且新版 Reader 上线后由 catalog 自动提供。仍沿用现有本地 provider、计费、访客限制、缓存与预取。

## 前后端链路

- Catalog 的 `target` 始终为字符串，增加 `goal: {kind, value}`。数值目标先按数字排序，再排列盘面和目标；AI 元数据排除盘面和。
- Lookup mask 保留盘面和目标的实际活动砖块，仅恢复变体的固定墙；旧目标遮罩不变，旧证据 mask 版本不变。
- 主站训练、测试、回放分析共用 `GoalPicker`：存在两种目标时选择类型和数值；单一种类时精简显示，保留访客选项提示。只显示服务器已有结果。
- Play 归档分析使用符合该站样式的 `NativeGoalPicker`。分析库、分析历史、排行榜与笔记展示友好标签；API、回放命名及跳转仍传完整原始目标标识。
- 浏览器本地走子在有效移动后判断边界。测试保留最后一步与 replay sentinel，停止后续输入/查询；训练停止自动演示和连续步进，允许撤销、改盘及重新选择。不会仅凭 100% 提前结束。
- 云端分析使用同一目标标识查询和预取；不再遮罩活动大数，盘面和分析从第一步开始计入；达标后停止，短片段仍输出报告和回放。
- 对战两种模式在前端过滤、后端拒绝盘面和目标，避免整数 target 和旧对战终止规则混用。AI 也显式过滤。Play 原有评级和展示图的目标限制保持不变。

## 验证

- 独立编译云端 `formation_core`，没有替换其他本地进程正在使用的扩展。
- `tests/test_sum_goal_cloud.py` 覆盖目标解析、遮罩、Catalog、Classic / EX / BC 缺终层文件时的合法达标查询、失败率 dtype、实际 EX 文件读取、早期 100% 仍分析、单步达标回放保留。
- 设置 `SUM_GOAL_TABLE_ROOT` 为上述两个目录的父目录后运行该测试，可验证真实表库；未设置时仅跳过三项真实文件及目录测试。
- `frontend/tests/goalTarget.test.js` 覆盖目标排序、标签、文件名识别、有效移动前后出数边界、取余、测试终止和回放。
- 同时运行现有分析、测试、catalog、训练、AI 与前端回归检查；前端三个入口由 Vite 一起构建。

## 发布顺序

1. 按 `AGENTS.md` 和 `deployment_retention.md` 验证线上构建基线，用明确的变更清单生成发布包，排除其他任务的未提交修改。
2. 上传两个目录到服务器本地表库根目录，校验文件大小及校验和，保留 zlut / metadata。
3. 发布新的 Python 与已重新编译的 native Reader、catalog 配置，然后发布主站及 Play 前端。
4. 检查目录中显示两个新目标，实际查表、训练、测试、上传回放和归档分析；确认旧数字定式及主站 Play/排行榜/AI 入口正常。
5. 按仓库要求检查发布保留策略与磁盘占用。

本次代码实施与本地验证不等同于已上传表库或已部署生产站。
