# 盘面和目标

## 使用方式与支持范围

在「设置 → 定式构建」中将目标类型选为「盘面和」，输入一个 **4 至 16382 的偶数**。用户看到的目标值不包含 16384、32768 方块。3×3、2×4、3×4 提供常用目标预设，也可自行输入。

| 算法 | 盘面和目标 |
| --- | --- |
| Classic | 支持，包括现有变体定式 |
| EX | 支持，包括现有变体定式 |
| BC | 支持原本已支持的定式，包括 free；没有增加变体支持 |
| AD / EXAD | 不支持；界面禁用，Python 和原生入口拒绝 |

盘面和目标不会扩展定式原有的合法局面范围。达到阈值的移动仍须有效、保持定式约束。目标低于或等于初始层的成功边界时，构建会明确拒绝，需选择更大的目标。

构建完成后，查表、训练、测试、回放分析的目标列表显示「盘面和 N」。配置中的路径注册仍沿用现有机制。数字组合目标暂不支持。

## 内部语义

设完整编码盘面和为 S，用户阈值为 T。成功判定顺序为：

1. 执行方向移动，盘面必须发生变化。
2. 检查移动后的盘面满足定式约束。
3. 检查 `S % 16384 >= T - 2`。

有效移动后必有空位，下次出数至少为 2，因此这里采用 T−2 边界。32768、16384 都是模数的整数倍。新合成 16384 不改变完整盘面和，也不改变该余数。这里刻意采用 Layer 盘面和的模数定义，不逐块求一个可能在合成时下降的「小数字和」。取模和 T−2 属于内部实现，界面只解释目标及下一次出数保证。

阈值最大为 16382，末尾两层不会跨越模数边界。一次构建只覆盖初始层所在的这个模数区间。目标条件不代表目标数字组合；例如盘面和 1792 不强制出现 1024、512、256。

## 层号与终端两层

保留旧层号定义：`layer = (S - S0) / 2`，S0 是定式旧 layer 0 的完整盘面和。负编号层规则不变。

设初始层号为 a，初始盘面和为 `Sa = S0 + 2a`，`B = Sa - Sa % 16384`。两层终端编号为：

```text
L = (B + T - 2 - S0) / 2
terminal_layers = [L, L + 1]
steps = L + 2
docheck_step = L - 1
```

必须满足 `Sa < B + T - 2`。生成仍按出 2 / 出 4 跨一层 / 两层。终端两层中的合法局面均以成功率 1 初始化，内层沿用现有递推、剪枝、分块、冷热路径、压缩和断点续算。

查表的方向判定仍先检查有效移动与定式约束。因此即使输入盘面超过阈值，无效方向或死局也不会自动得到 1。终端有效方向可直接返回成功率，无需依赖终端文件是否被剪枝或归档。

## 成功目标与编码参数分离

`engine_core/GoalSpec.py` 是 Python 层的共同定义：解析、校验、编码指数、层范围、元数据和目标列表。

原生 `RunOptions.target` 继续表示编码所用的砖块指数；新增 `sum_target`，0 表示旧单砖块目标，否则表示 T。普通 sum 编码上限使用 `floor(log2(T))`，不能以「遇到这个砖块」判成功：例如 sum-1792 中遇到 1024 后必须继续递推。

- Classic 生成关闭原来的目标砖块分支截断，按终端层停止；回算统一调用 goal predicate。
- EX 保留原有 LUT / 编码结构，生成范围及回算终端由 sum goal 决定。
- BC 将 `success_target_rank` 置 0，resident / single / family 共用 sum predicate；生成最后两层不再按单砖块目标筛选。含固定 16384 的种子需要在 BC 合法砖块集合中保留 rank 14，构建和 reader 使用相同规则。
- AD / EXAD 仍依赖目标砖块与大数排列的耦合。此次显式禁用，避免把某个编码阈值误认作成功。

## 文件与兼容

新目标使用独立标识 `sum-N`，例如 `3x3_sum-1792_`、`free12_sum-1792_`。单砖块目标仍使用原来的数字标识，文件名、成功语义和格式不变。

原有 `.book`、EX、BC 数据格式均不变。在结果前缀旁新增 `<prefix>goal.json`：

```json
{
  "version": 1,
  "kind": "sum",
  "value": 1792,
  "semantics": "post_move_mod16384_target_minus_2",
  "encoding_rank": 10,
  "layer_zero_sum": 229376,
  "layer_offset": 0,
  "terminal_layers": [895, 896],
  "algorithm": "ex"
}
```

上述示例为 3×3 的固定墙盘面。冷热路径都保存元数据；续算时校验已存在的元数据一致，防止混用目标、层定义或算法。reader 通过 `sum-N` 标识恢复目标，使用原有全盘和索引查找，旧表不要求补元数据。

脚本入口 `start_build` / `v_start_build` 原来的整数参数继续表示目标指数；新目标传字符串 `"sum-1792"`，输出前缀也必须包含这个标识。不需要新增独立续算流程。

## 查表、训练与分析

- Dispatcher 按目标标识寻找 Classic / EX / BC 文件，并按同样的目标缓存 reader。
- sum 模式保留活动区域内的所有真实数字，不用编码上限把大数字替换成占位块；变体仍恢复固定墙。
- 各种成功率精度保持原有表示，`1-float` 的终端存储 / 返回值为 0，其余格式为 1。
- 随机训练局面避开已经达到成功边界的局面，最多尝试 64 次；没有可用局面时沿用空结果处理。
- 训练按实际执行的有效方向判定完成，状态中返回 `goal_reached` 并停止自动演示；仍保留原有出数和回放记录结构。盘面编辑或切换定式后状态重新计算。
- 回放分析不再因为「最优成功率恰为 1」就提前结束。只有实际执行的合法移动满足目标，才结束这个目标的分析。

### 周边功能复查与补充适配

- **测试模式**：成功率为 1 不再提示即将合成目标砖块。只有实际移动满足 sum 目标才结束本轮；出数与成功那一步的回放仍保留，继续走子的请求被忽略。
- **分析模块**：sum 目标从第一步起记录和评分，不沿用单砖块残局的前几步跳过规则；短分析也输出报告，一步回放也可保存。达到目标后停止遍历，报告文件中的步数对应实际终点。
- **训练自动走子**：`1-float` 中的 0 表示成功率 1，不得按假值忽略。按还原后的概率决定是否能自动走子。
- **多页查表**：各会话独立持有 Dispatcher，避免训练页和测试页选择不同目标后覆盖彼此的算法、目标和 LUT。分析实例本来就独立持有 reader。
- **回放跳转训练**：备用文件名识别同时接受 `3x3_1024_...` 与 `3x3_sum-1792_...`。后端回放识别、目标列表、错题本键及训练跳转参数均按完整字符串传递，不要求目标是数字。
- **原生查询及格式**：本轮无需进一步修改原生代码。实际生成的 Classic / EX 表已验证 Dispatcher → 测试走子 → 分析报告 → 回放重新读取链路；BC 原始 / 压缩及各回算路线保留原有专项覆盖。

补充适配后，共 **38 项专项与相关回归通过**，回放文件名兼容检查 5 项通过，前端构建通过。完整流程测试还验证了同时打开不同目标的会话、早期成功率 1 不提前终止、短报告包含所有有效步骤、终端回放盘面与测试实际盘面一致。

## 验证

`tests/test_sum_targets.py` 使用独立的 Python 2×2 移动和 Bellman 递推作为基准，验证包含 0 与 1 之间概率的 Classic 逐局面结果；还覆盖 EX 原始 / 压缩读取、BC 三条回算路线、压缩续算、终端方向、六种数据精度、非法阈值、AD 拒绝、实际 Python 构建入口与元数据一致性。与负层号、AI 相关回归共同执行通过。

原生模块使用独立的 `native_core/build-sum-goal` 编译验证；前端也先使用独立输出目录。验证后已更新本地原生模块与 `frontend/dist`，使用正式模块路径执行的专项与相关回归共 **36 项通过**。已有进程继续使用它们已加载的原生模块，重启应用后使用新版本。没有对用户已有的大型定式重新计算。
