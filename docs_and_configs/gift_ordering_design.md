# 礼物排序与常驻栏设计

> 状态：已于 2026-09-27 上线。

## 现状

礼物模块已经与直播内容解耦，`GiftPanel` 由房间外壳挂载。送礼价格、目录、幂等订单、连送与余额均由共享礼物服务处理，因此排序只能是账号级展示偏好，不能进入价格快照或订单指纹。

当前全部礼物按照后端 `GIFTS` 目录顺序展示；下方常驻栏则在前端硬编码为 `two / four / heart / flowers / moai / button / tea / whale / rip` 九项。红包是单独的房间活动操作，当前已经插在全部礼物首位，且从未进入常驻栏。

## 结论

只维护一条完整的礼物顺序，不再维护独立的“常驻礼物”集合。顺序中的前九项就是下方常驻栏；第十项起只在全部礼物中显示。这样一次拖动同时表达排序和常驻选择，不会产生顺序、置顶状态和数量上限之间的冲突。

红包保持固定在全部礼物第一位，但不属于礼物顺序，不计入九项，不显示序号，也不能拖动。下注、福袋等房间活动继续占用礼物栏的 leading 插槽，不计入九项。

## 抽屉交互

全部礼物抽屉的标题栏增加“调整顺序”。普通模式继续沿用现有点击、悬停批量选择和送礼行为。进入调整模式后，礼物卡不再触发送礼或数量浮层，改为独立的排序卡，避免拖动时误消费。

抽屉自上而下显示：

1. 红包固定操作，使用横向单行或全宽卡片，并标注“固定在首位”；没有红包能力的房间不显示。
2. “常驻栏 · 前 9 个”区域，恰好三行三列。
3. 一条明显但克制的分界线，文案为“以下仅在全部礼物中显示”。
4. 其余礼物，继续使用三列网格。

排序模式为每张卡显示序号和拖动把手。桌面端从把手按下即可拖动；触屏端同样从把手拖动，把手设置 `touch-action: none`，卡片其他区域仍可正常滚动抽屉。拖动接近抽屉上下边缘时缓慢自动滚动，落点使用插入线表示。跨过第 9 项分界线时，下栏预览立即更新。

键盘操作与拖动结果等价：把手获得焦点后，左右方向移动一位，上下方向移动三位；屏幕阅读器通过 `aria-live` 播报“已移至常驻栏第 4 位”或“已移至全部礼物第 12 位”。不依赖 HTML5 原生拖放，以免触屏浏览器行为不一致。

标题栏在排序模式改为“取消 / 调整礼物顺序 / 完成”，并提供“恢复默认顺序”。调整只修改草稿；“完成”一次保存，取消、关闭或 Esc 放弃草稿。拖动过程中可以预览下栏，但取消后恢复原顺序。

普通模式下保留一句短说明：“前 9 个礼物显示在下方常驻栏。”不长期显示序号和分界说明，避免增加购买界面的视觉负担。

## 默认顺序与目录变化

现有用户首次启用时，应保持当前常驻栏不变。默认完整顺序为：先放当前九项常驻礼物，再按后端目录顺序追加其余礼物并去重。

读取保存值时统一执行归一化：

- 只保留当前目录中存在的 ID，并去重；
- 新增礼物按服务器目录顺序追加到末尾，不会突然挤入用户的常驻栏；
- 下架礼物自动移除；
- 空值、损坏值或未保存用户回到默认顺序；
- Top 9 始终从归一化后的完整顺序派生。

如果将来运营上需要让新礼物默认进入常驻栏，只影响从未自定义过顺序的账号；已经保存过顺序的账号仍将新礼物追加到末尾。

## 数据与接口

排序属于共享礼物模块和账号，不属于某个直播房间。建议在现有 `live_gift_preferences` 增加 `gift_order_json`，后续对战页复用同一礼物服务时自然得到相同顺序。无需修改通用外观偏好，也不按房间保存。

新增独立接口，例如 `POST .../gifts/preferences/order`：

```json
{
  "gift_ids": ["two", "four", "heart", "flowers", "moai", "button", "tea", "whale", "rip"]
}
```

客户端实际提交当前所见的完整目录顺序；服务端限制数组长度和字符串长度，去重并按当前目录归一化，再返回最终顺序。`GET .../gifts/me` 同时返回 `gift_order`。使用独立接口可以避免改动每日预算和赞助者入场设置的现有写入语义。

同一账号多设备采用最后一次完整保存成功的顺序。礼物目录、价格版本和订单请求都不包含该顺序，重新排序不会改变报价版本、待发送队列或连击。

为减少首次渲染跳动，可以按账号 ID 缓存最后一次成功顺序；服务器结果返回后再归一化覆盖。缓存只用于即时显示，服务器值是跨设备权威值。

## 代码边界

- 新建无 UI 的 `giftOrder.js`，负责默认顺序、目录归一化、移动和 Top 9 派生。
- `GiftPanel.vue` 持有已保存顺序与排序草稿，常驻栏和全部礼物都从同一个计算结果生成。
- 排序模式使用单独的 `GiftSortCard.vue`；现有 `GiftChoice.vue` 保持购买交互，不混入拖动分支。
- `backend/gifts/service.py` 保存账号顺序；直播和未来对战的宿主路由只转发认证用户，不保存房间级副本。

## 验证范围

- 默认用户仍看到目前九项常驻礼物；红包始终第一且永不进入下栏。
- 将第十项拖入前九后，下栏立即按新顺序更新；把前九项拖出后由第十项补位。
- 鼠标、触屏、键盘均可重排，拖动不会触发送礼或数量浮层。
- 取消、Esc、保存失败均不覆盖已保存顺序；重试成功后跨房间和跨设备一致。
- 新增、下架、重复及未知礼物 ID 能正确归一化。
- 排序不改变目录报价版本、订单指纹、待发送请求、红包、下注或福袋状态。

## 上线记录（2026-09-27）

已按本设计实现账号级完整排序。全部礼物抽屉支持鼠标、触屏拖动与键盘方向键调整；排序前九项即时预览并构成下方常驻栏。红包固定在全部礼物首位，不计入顺序及九项额度。保存后的顺序由服务端归一化并跨房间、跨设备读取，新增或下架礼物按本设计自动补齐或移除。

生产数据库已增量加入 `live_gift_preferences.gift_order_json`；匿名写入排序接口返回 `401`，服务保持 `active`。上线前通过 535 项前端测试、46 项礼物/直播路由后端测试及生产构建；公开页面已核验默认常驻九项、全部礼物顺序和红包固定说明。
