# Battle V1 前端界面与交互规范

更新时间：2026-08-30。本文基于 `src - cloud` 云版副本，先冻结界面与控件契约，再实施 Vue 页面。

## 1. 页面状态

Battle 使用一个独立 Tab，页面内部只有四种顶层状态：

- `hall`：公开房间列表、房间码加入、创建房间。
- `preparing` / `lobby`：路线生成中或候场房间。
- `playing` / `spectating`：参赛或观战。
- `result`：本轮结果；确认后回到原房间，设置保留、准备状态清空。

刷新或 WebSocket 重连后，页面先调用 `GET /api/battle/me` 恢复当前房间，再订阅房间快照。一个用户同时只能存在于一个房间。

## 2. 对战大厅

桌面布局为左右两列，左侧约 2/3，右侧约 1/3：

- 左侧顶部：标题、简短规则、刷新图标按钮。
- 左侧主体：公开房间表格。列为房主、定式、玩家数、状态、观战、加入命令。
- 右侧第一块：6 位房间码输入和“加入房间”按钮。
- 右侧第二块：“创建房间”表单。

创建表单控件：

- 定式 pattern 与 target：使用 catalog 联动选择器，只显示在线定式。
- 初始盘面：16 位十六进制输入；留空表示 Trainer Default 随机局面。
- 玩家上限：数字步进，范围 2–8，默认 2。
- 最大步数：数字输入；留空表示无用户上限。
- 单步限时：选择器，15/30/45/60 秒，默认 30。
- 公开房间、允许观战：两个开关。
- 费用预览：内测阶段只读显示 `5 × 定式倍率` 和当前余额。
- 创建按钮：路线生成期间显示忙碌状态，不允许重复提交。

V1 仅支持登录用户；未登录时页面显示登录入口，不请求或展示房间列表。登录后才能浏览大厅、加入、创建或观战。

## 3. 候场房间

顶部固定显示房间码、复制邀请链接、定式和路线状态。主体左右两列：

- 左侧为 2–8 个玩家座位，显示头像、用户名、房主标记、在线/准备状态。
- 右侧为房间设置摘要、观战者列表和房主控制。

交互规则：

- 有空位时，加入者可用分段控件选择玩家或观战者；满员时只允许观战。
- 玩家使用“准备”开关；至少 2 人且所有玩家准备后，房主“开始”按钮可用。
- 房主可在开赛前踢出非房主玩家；被踢用户本房间生命周期内不能重新加入。
- 路线相关设置创建后只读。下一轮使用相同设置生成新路线并再次计费。
- 离开房间是明确命令；开赛后参赛者离开视为本轮放弃。

## 4. 对局布局

参赛视图使用左主右辅两列：

- 左侧：当前棋盘、路线进度条、单步倒计时。
- 右侧：自身累计吻合度和最多 7 张对手状态行。
- 对手状态行只显示头像、用户名、吻合度、进度和在线状态。
- 当前玩家完成前，不渲染对手棋盘；完成后在对手状态行中实时显示其当前棋盘。

键盘与滑屏输入沿用现有 2048 控件，不提供方向按钮。非法方向只触发轻微棋盘反馈，不推进路线，也不重置倒计时。

合法但非最优时，在棋盘内部显示覆盖层：

```text
本步已纠正
你的走法：左
最优走法：下
吻合度下降：3.24%
```

覆盖层不显示方向成功率，约 900ms 后关闭并播放标准方向动画。覆盖和动画期间锁定输入。

到达 `certainty_step` 后立即冻结成绩并标记完成；余下标准路线自动播放到目标棋块，不再接受输入或改变吻合度。

## 5. 观战布局

观战者使用 2×4 棋盘网格；玩家较少时自动收缩到 2×2 或单行。每个小棋盘显示玩家头像、用户名、吻合度、进度、在线和完成状态。观战者不显示输入焦点和倒计时操作状态。

## 6. 结果布局

结果使用无嵌套卡片的全宽列表：名次、头像、用户名、最终吻合度、完成/超时/离线状态。相同服务端吻合度并列，不显示用时排名。所有玩家完成后服务端将房间恢复为候场状态；客户端关闭结果后看到原房间，所有准备状态为未准备。

## 7. 响应式与可访问性

- 沿用项目当前固定横向工作区，不新增竖屏专用分支。
- 对局主棋盘保持稳定尺寸，右栏允许内部滚动，不能覆盖棋盘或顶部 tab。
- 状态不能只依赖颜色，同时显示短文本或图标。
- 所有按钮具有禁用态，禁用态外观必须明显。
- 中英文文本均预留最长文案宽度；状态标签使用短翻译。

## 8. 前端数据契约

页面只消费以下稳定模型：

- `room`：房间码、状态、设置、过期时间、路线状态、当前轮次。
- `members`：用户公开资料、角色、座位、准备、在线、完成状态。
- `route`：二进制 17-byte 记录、步数、certainty step、hash、终止原因。
- `selfResult`：服务端确认序号、路线位置、累计吻合度、deadline。
- `roundResults`：最终名次与状态。

所有命令带 `request_id`；所有房间快照带递增 `revision`，旧事件不得覆盖新状态。
